# Spike 002: Per-phase A/B vs C++ at low rows

## What This Validates

**Given** a 2k-row regression train, **when** the Rust CPU-anchor and C++ LightGBM 4.6
train loops are decomposed into matching phases and diffed, **then** the fixed
~188µs/iter low-row gap is localized to specific phase(s) — turning "1.9–2.9× slower"
into "Rust overspends Nµs in phase X."

## Method

Matched config both sides: 2k rows × 12 feats, identity-binned (32 distinct values),
regression, 100 iters, 31 leaves, lr 0.1, min_data_in_leaf 20, **single-thread**.

- **C++ side:** built `lib_lightgbm` 4.6 CLI with `-DUSE_TIMETAG` (`cmake -B
  build-timetag -DUSE_TIMETAG=ON`). Its `global_timer` emits per-phase wall-clock
  tags (richer than expected — covers the serial CPU learner). Synthetic data
  generated by `gen_data.py` mirrors the Rust bench corpus exactly. Stable numbers =
  **min over 5 runs** (wall-clock is noisy at this tiny scale: 4× run-to-run spread).
- **Rust side:** env-gated phase profiler `lgbm_treelearner::phase_prof` (inert unless
  `LGBM_PHASE_PROF=1`; verified zero-overhead — 39.35ms with it off == 41ms baseline).
  Wraps the growth-loop phases: `before_find_best_split`, `find_best_splits`
  (build+scan fused), `split_inner` (partition); plus RAII guards inside
  `build_leaf_histogram_into` (BUILD) and `scan_leaf_histogram` (SCAN).
- **Cross-check:** `callgrind --cache-sim=yes` on the Rust binary.

## How to Run

```bash
# C++ phase tags (min over 5 runs)
cmake -B LightGBM/build-timetag -S LightGBM -DUSE_TIMETAG=ON -DBUILD_CLI=ON -DCMAKE_BUILD_TYPE=Release
cmake --build LightGBM/build-timetag -j
cd .planning/spikes/002-lowrow-phase-ab && python3 gen_data.py small.csv
../../../LightGBM/lightgbm config=train.conf num_iterations=100   # reads 'costs:' tags

# Rust phase breakdown
LGBM_PHASE_PROF=1 BENCH_SIZES="small:2000:12:32" BENCH_ITERS=100 BENCH_REPS=4 \
  cargo run --release --example bench_crossover     # prints [phase_prof:...] to stderr
```

## Investigation Trail

1. **C++ TIMETAG coverage check** — first grep suggested the serial learner had no
   tags; a real `-DUSE_TIMETAG` run proved otherwise (tags live in headers/macros).
   Got a full CPU-path breakdown for free.
2. **perf blocked** (`perf_event_paranoid=4`, no privileges) → pivoted to TIMETAG +
   callgrind (both permission-free).
3. **callgrind was confounded** — the profiling binary statically bundles LLVM (via
   `cubecl-cpu`), so ~52% of instructions ran *before main* (LLVM static init). Clean
   takeaways survived: (a) **not cache-bound** at 2k (LL miss 0.1%); (b) malloc / free
   / memset / memcpy ≈ **22% of in-main instructions** = allocation churn.
4. **Separated fixed vs per-iter** via an iters sweep {1,5,20,100} on the *release*
   binary: fixed startup ≈ **350µs one-time** (cubecl client/runtime init — 0.85% at
   100 iters), per-iter ≈ **~418µs steady-state**. So the gap is per-iteration work,
   NOT JIT/startup. (Cold first train ≈ +116ms once/process — amortized by rep 2.)
5. **Instrumented Rust phases** → localized the gap (below).

## Results

**VERDICT: VALIDATED.** The low-row gap is ~entirely **histogram construction (build)**.

Per-iter, matched config (Rust warm; C++ min-of-5):

| phase | Rust µs/iter | C++ µs/iter | Rust/C++ | gap µs/iter |
|-------|--------------|-------------|----------|-------------|
| **histogram build** | **232** | **44.5** | **5.2×** | **187.5** |
| split scan | 73.5 | 52.1 | 1.4× | 21.4 |
| partition | 49.6 | 24.1 | 2.1× | 25.5 |
| before / gates | 0.6 | 2.0 | — | — |
| grad-hess + score-update | ~tiny | ~1.6 | — | — |
| **train total** | **~393** | **143.8** | **2.7×** | **~250** |

Rust phase shares (warm): histogram **build 62.7%**, split scan 19.9%, partition
13.4%, before 0.2%. C++ shares: ConstructHistograms 32%, FindBestSplits 37%,
SplitInner 17%.

**The histogram-build gap (187.5µs/iter) alone ≈ the entire low-row gap.** Split scan
and partition are near parity (1.4×, 2.1×). The bottleneck is the per-feature
row-major `Vec<Vec<f64>>` gather in `build_leaf_histogram_into` (called once per
feature per leaf) + its allocation churn — exactly the callgrind 22% malloc/memset/
memcpy, which lives *inside* this phase.

### Surprises

- C++ TIMETAG covers the serial CPU learner richly (first grep was misleading).
- callgrind on a cubecl-cpu binary is dominated by bundled-LLVM static init — useless
  for per-iter attribution; the env-gated wall-clock profiler was the right tool.
- **Not cache-bound at low rows** (LL miss 0.1%) — so the build gap here is
  instruction/dispatch/alloc overhead, not cache misses. (Cache misses are a separate
  *large-row* concern; this spike is low-row.)
- A ~116ms cold-start (cubecl client init) hits the first train per process. Harmless
  for one long run; could bite a process-per-train CV/hyperparam-search harness.

### Caveats

- One shape (2k×12, 32 bins). The *proportions* should generalize at low rows but the
  exact crossover of phase dominance shifts with feature/bin/leaf counts.
- C++ wall-clock is noisy at this scale; used min-of-5. Rust used the env-gated
  profiler (deterministic accounting, ~zero overhead).

## Signal for the Build

- **Fix histogram construction first** — it's 63% of low-row train time and 5.2×
  slower than C++; everything else is near parity. Two stacked levers, both targeting
  this one phase:
  1. **Kill the alloc churn** (seed `reuse-tree-learner-scratch-across-iters`):
     reuse the per-feature gather / histogram buffers across iterations instead of
     re-allocating + re-zeroing per feature per leaf. CONFIRMED relevant (22% of
     in-main instructions are malloc/memset/memcpy inside the build).
  2. **Columnar pre-binned storage + subtraction reuse** (roadmap R3): replace the
     row-major `Vec<Vec<f64>>` per-feature gather with C++-style columnar binned
     storage so the build inner loop is tight/SIMD-friendly. The structural fix.
- Do NOT chase split-scan or partition for low rows — they're already ~1.4–2.1× and
  account for <20% of the gap.
- Reusable deliverables kept in-tree: `lgbm_treelearner::phase_prof` (env-gated),
  `[profile.profiling]` in Cargo.toml, `bench_crossover.rs` dump hook.

# Milestone v1.1 Audit — CUDA On-Device Training Backend (Phases 14–23)

**Audited:** 2026-07-03 · **Status:** ⚠ `gaps_found`

## Verdict summary

The v1.1 on-device CUDA training pipeline is **built, anchor-pinned, and cross-phase wired for the path it ships**, and the hard merge gate is green (963 passed / 0 failed with `LGBM_CUDA_ON_DEVICE` unset — every CPU/ROCm/host-CUDA path byte-unchanged). Nine of ten phases are independently verified `passed`. This is strong, correct work.

It is **not** a clean `passed` milestone, for three honest reasons — none of which are broken functionality:

1. **Phase 23 is unverified** — no `23-VERIFICATION.md` exists. The phase closed DoD-complete via its SUMMARYs + `results.md` evidence, but ended on the human-verify FAIL branch and never ran the verifier gate. Per GSD's audit rule, a phase missing VERIFICATION.md is a blocker.
2. **ODL-21 (the headline DoD) was not literally achieved** — on-device did not become the default. The requirement is *contingent* on the A/B being not-slower; the real-CUDA A/B **FAILED** (launch-bound, ~23 min/100-tree arm), so the default-on flip was correctly **withheld**. The contingency logic worked as designed; the literal end-state ("on-device is the default") is not met, and on-device stays opt-in.
3. **The "host only orchestrates" intent is partially realized** — 7 anchor-pinned kernels (objectives ODL-05..08, metric ODL-17, device dataset + row-gather ODL-03/04) are not consumed by the production driver, so gradients, metric eval, and leaf-row gather still round-trip through host each boosting iteration. All are documented per-phase deferrals.

## Cross-phase integration

**PASS — 0 wiring blockers.** The on-device tree-grow driver (`grow_tree_on_device_driver_with_cfg`, `crates/lgbm-compute/src/kernels/grow_driver.rs:617`) sequences the full per-leaf best-first loop, and every primitive it calls resolves to a real exported kernel across P14→16→17→18→22: root fold → `construct_histograms_f64_on` (P16) → FixHistogram/compaction → `find_best_split_f64_on` (P17) → `DeviceCudaTree::split_on_device` (P18) → `partition_leaf_stable` (P18) → subtract trick (P16) → categorical branch (P22). It reconstitutes into `(Tree, LeafPartitionLayout)`, and the learner seam (`CpuBackend::grow_tree_on_device`, `lib.rs:1423`) feeds `DataPartition::from_payload` → the 4-tuple the GBDT boosting loop consumes. On-device resident score update wired at `gbdt.rs:1593` (gated on `boosting_on_cuda()`).

**Gating integrity: PASS.** `on_device_default()` = `false`; `cuda_on_device_enabled()` = tri-state override with a second independent re-check inside the seam body; learner fork is dead with the env unset; merge gate 963/0 byte-unchanged. The parity oracle (`assert_on_device_tree_matches_cpu_anchor`) anchors on-device STRUCTURE to the cpu f64 fold, non-vacuous under `LGBM_CUDA_ON_DEVICE=1` — never GPU-vs-GPU.

**WARNING — 7 unwired requirements (DoD-intent gap):** ODL-03, ODL-04, ODL-05, ODL-06, ODL-07, ODL-08, ODL-17 are anchor-pinned reusable kernels with no production consumer. See tech debt.

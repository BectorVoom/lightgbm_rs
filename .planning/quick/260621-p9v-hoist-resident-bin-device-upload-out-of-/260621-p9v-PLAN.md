# Quick Task 260621-p9v: Hoist resident-bin upload out of the per-tree hot path

## Problem (spike-014b)

`learner.rs:826` (inside `train_inner`, which runs **once per tree**) unconditionally
re-uploads the binned feature matrix to the GPU every tree: `to_u32_vec` widens it
(2GB host alloc at 1M×500), `upload_resident_bins` concatenates a 2nd 2GB buffer +
`create_from_slice` uploads 2GB host→device. The binned columns are **immutable for the
whole train**, so every tree after the first is pure waste — measured **~31% of train
wall-clock at 1M×500** (spike-014b `resident_bin_upload` = 93% of `in_learner_other`).

## Why it's safe to upload once

- `RocmBackend` is **one instance per `train()`** (booster.rs:1086-1091), so its
  `resident_bins` cache persists across all trees in the train.
- `reset_resident_pool` (lib.rs:2156) clears only the histogram-slot mirror
  (`resident_pool`), **never** `resident_bins` — so the bin cache survives across trees
  and pool resets. Nothing else clears it (only set sites: lib.rs:2046/2060).
- ⇒ After the first tree uploads, the cached device `Handle` is reusable byte-for-byte
  by every subsequent tree. Parity-neutral (same bytes, uploaded once).

## Task 1 — add a once-per-train upload guard

**Files:** `crates/lgbm-treelearner/src/learner.rs`

- **action:** Add a `resident_bins_uploaded: bool` field to `SerialTreeLearner`
  (next to `fused_eligible`). Init `false` in `new()`. Reset `false` in `with_features`
  (feature set changed ⇒ the cached bins are stale ⇒ must re-upload). Guard the
  `wants_resident_bins()` block at `learner.rs:826` with `&& !self.resident_bins_uploaded`
  and set `self.resident_bins_uploaded = true;` after `upload_resident_bins` returns.
  Keep the `phase_prof::UPLOAD_NS` guard (it now only fires on the first tree).
- **verify:** `cargo build` + `cargo build --features rocm`; bit-exact gate
  `cargo test -p lgbm-treelearner --lib`, `cargo test -p lgbm-boosting --lib`,
  `cargo test -p oracle-harness`.
- **done:** Builds clean; all parity tests green.

<objective>
Reduce the profiled GPU bottleneck — launch count — on the device-resident per-leaf
histogram build. Two independent levers, both GPU-only:

- **Lever A (widen-fold, universal):** fold the standalone `widen_f32_to_f64_kernel`
  launch INTO the `fix_compact_kernel`. The fix kernel reads the f32 RAW histogram
  directly, widens each cell inline (`f64::cast_from`, identical cast to today's
  widen), and writes the fixed+compacted f64 result into the f64 output. The resident
  build drops from 3 launches to 2. BIT-EXACT BY CONSTRUCTION — same f32→f64 cast,
  same fold order, same f64 fix math already proven bit-exact in oib.

- **Lever B (size-gate, perf knob):** add a `num_data` condition to `resident_eligible`.
  Below a measured crossover threshold the workload uses the existing (pre-p90) host
  fix path (the eligibility gate already falls back safely); at/above it uses the
  resident path. The threshold is DATA-DRIVEN — bench small/medium/large BOTH ways
  AFTER lever A, find the crossover, set the threshold, report the numbers.

Purpose: stop the p90 resident path's extra launches from regressing small
(launch-bound, −13%) while keeping medium (+10%) and large (flat, compute-bound).

Output: a folded 2-launch resident build kernel, a size-gated eligibility predicate
with a justified threshold, refreshed bit-exact oracles, and honest before/after
GPU bench numbers.
</objective>

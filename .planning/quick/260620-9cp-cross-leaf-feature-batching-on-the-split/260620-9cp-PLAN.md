<objective>
Parallelize the per-leaf, cross-feature best-split scan in the CPU backend so a SINGLE rayon
fork/join is amortized across ALL features of a leaf — replacing the serial `for f in feats`
loop at `crates/lgbm-compute/src/lib.rs:574`. Each `find_best_split` already reads a DISJOINT
histogram region (`buf[f.slot_off..end]`) and produces an independent `SplitInfo`; the caller
(`scan_leaf_histogram` in `crates/lgbm-treelearner/src/learner.rs:1870`) does the cross-feature
argmax SERIALLY over the returned Vec in feature order. So preserving feature-index output order
makes the result byte-identical.

This is FUNDAMENTALLY different from the rejected quick 260620-8v4 lever (REVERSE∥FORWARD on two
rayon lanes PER find_best_split CALL → fork/join paid per (feature,leaf), ~13× slower). This lever
pays ONE fork/join per leaf, amortized across ~120 features on the wide config. SCAN was profiled
at 44% of (BUILD+SCAN) on the wide config, so a real win moves warm train wall time.

Purpose: Cut warm-train wall time on wide configs without touching per-feature f64 accumulation order.
Output: Ordered, size-gated parallel scan in CpuBackend; env-tunable `LGBM_PAR_SCAN_THRESHOLD`;
A/B measurement; HARD bit-exact parity merge gate (CPU f64 anchor authoritative).
</objective>

<objective>
Wire spike-029 (VALIDATED ~1.2-1.7×, bit-exact, rocm 3 restarts) into the ROCm
partition path: the per-split device op uploads the leaf's bins at NATIVE width
(u8/u16/u32) instead of u32-widened.

Purpose: cut the per-split host→device upload + kernel-read by 4× on the common
all-u8 (max_bin≤255) case (first-order on a discrete gfx110x PCIe bus; sign-stable
~1.2-1.7× even on the spoofed shared-DDR5 APU). Bit-EXACT by construction — the
u8/u16/u32 kernels read the same bin value via `u32::cast_from`, so routing is
value-identical → byte-identical route → byte-identical (reordered, split_point).

Output: a width-aware ROCm partition path behind an ADDITIVE Backend method, with
the narrow path parity-covered by a U8 (and U16) BinColumn cell on both cpu and hip.

Design is ADDITIVE (mirrors how spike-027 added `prefers_host_partition` rather than
mutating existing signatures): the existing `data_partition(&[u32], …)` trait method
and every caller stay byte-unchanged; only a new sibling method is overridden on
RocmBackend.
</objective>

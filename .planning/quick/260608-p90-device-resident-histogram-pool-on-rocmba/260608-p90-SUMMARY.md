## Architecture / Wiring

- **Device-handle slot mirror** (`RocmBackend.resident_pool: RefCell<Vec<Option<Handle>>>`) keyed by host `HistogramPool` slot id. The learner reuses the host pool's `get`/`move_` slot decisions and issues the parallel device op at the SAME call site with the SAME slot ids — no reimplemented LRU / tree-growth.
- **Slot-id stability:** host `pool.move_` rewires leaf->slot WITHOUT changing the physical slot id (`larger_slot == parent_slot`, asserted). The mirror is slot-id-keyed, so the parent Handle is already at `parent_slot` when the resident subtract reads it — `move_resident` is a defined-but-unused no-op (documented).
- **Single-source fused scan:** `find_best_splits_batched_fused_f64_on` (host buf) now uploads once and delegates to `find_best_splits_fused_inner`; `find_best_splits_batched_fused_f64_from_handle_on` (resident) calls the SAME inner body with a device Handle — guaranteeing byte-identical numerics.

## Deviations from Plan

### Auto-applied (Rule 3 — blocking issue: kept the seam compiling)
- **subtract kernel + RocmBackend subtract_resident/move_resident landed in T1, not T2.** The plan scopes the Handle-in/out subtract kernel to T2A, but the RocmBackend `subtract_resident` override (which calls it) is part of the T1 seam ("define now so the seam is complete"). To keep T1 compiling, `subtract_histograms_f64_from_handles_on` was added in the T1 commit alongside the override. T2 added only the LEARNER wiring (routing the larger child resident) + the tree-equivalence test — which is the substantive T2 work. No behavior shipped early (the kernel is unreachable until the T2 learner wiring calls it).

### Design decision (documented, not a deviation from intent)
- **move_resident is not invoked by the learner.** The plan's step 2B/2C describe calling `move_resident` at the `pool.move_` site. Analysis showed the device mirror is slot-id-keyed and `pool.move_` preserves slot ids, so a device move is unnecessary (and would be incorrect for a slot-id-keyed mirror). The seam method exists per the plan's "define now so the seam is complete"; the correct wiring relies on slot-id stability (asserted via `debug_assert_eq!(larger_slot, parent_slot)`). The resident==host tree-equivalence test (max 9.0e-7) confirms the mirror tracks the host pool correctly without a move.

### Out of scope (verified pre-existing)
- **D-03a `kernel_parity_split_within_tol_on_hip` FAILS** at HEAD and after this work, identically (`skip_default_bin_false default_left left:true right:false` + ~3.8e-6 forward-winner gap). Verified failing at HEAD in Task 0 BEFORE any change. The plan explicitly scopes the f32 split gap OUT. NOT a p90 regression.

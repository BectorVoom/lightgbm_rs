<objective>
Parallelize the GPU histogram-subtract kernel from a single lane (`UNIT_POS == 0`) to a
grid-stride workgroup, keeping it byte-identical. Per the verified scope correction, the LIVE
GPU subtract path uses the **f64** `subtract_hist_kernel` (not the f32 mirror): `subtract_resident`
(lib.rs:2324) → `subtract_histograms_f64_from_handles_on`; `RocmBackend::subtract_histograms`
(lib.rs:2050) → `subtract_histograms_f64_on`. Both dispatch the f64 `subtract_hist_kernel` at
`CubeCount::Static(1,1,1) × CubeDim::new_1d(1)`. CubeCL profiling attributed ~32% of GPU
device-kernel time to that kernel. The f32 mirror (`subtract_hist_kernel_f32`, only live caller =
the hip f32 parity test) is parallelized identically for consistency.

Purpose: remove the 1-lane device kernel — a correctness-shaped cleanup. The op is pure
elementwise (`out[i] = parent[i] - child[i]`), no atomics / no reduction / no cross-element or
cross-thread dependency / no ordering, so disjoint threads produce the byte-identical result as
the serial loop on ANY backend. This is byte-identical, NOT a ~1e-6 relaxation.

Output: parallel f64 + f32 subtract kernels with real-grid launch dims at every cubecl launch
site, a `subtract_parallel_equals_serial` bit-exactness test for both, the bit-exact merge gate
green, and an honest re-measurement of the subtract device-time share.

NON-GOAL / DO NOT TOUCH: `subtract_histograms_cpu_native` (subtract.rs:128) — the native Rust CPU
production anchor — is a separate non-cubecl path and stays byte-unchanged.
NO wall-clock win is required: on the spoofed 8-CU APU the GPU loses to the CPU overall. The
deliverable is the device-time-share reduction + correctness (no 1-lane kernel) + proven
bit-exactness.
</objective>

    multiple of the grid size) — this is what makes the launch grid robust to arbitrary `len`.
    Add a one-line doc note on each kernel that the loop is bit-exact-by-construction (independent
    cells, no atomics/reduction/ordering) so the parallel shape is byte-identical to the serial one

# Quick Task 260625-tw1: Re-wire LGBM_SCAN_DRAIN on the co-pack scan path

## Problem (root cause, confirmed by reading the code)

`LGBM_SCAN_DRAIN=1` is meant to force-drain the async-queued f32-atomic histogram BUILD
(by reading the resident histogram handle BEFORE the scan launch) so build device-compute is
attributed to `SCAN_DRAIN_NS` instead of materializing inside the scan readback — the spike-015
re-attribution that spike-023 used ("build 86%→92%, scan 14%→8%").

That drain block exists ONLY in the single-leaf scan `find_best_splits_fused_inner`
(`crates/lgbm-compute/src/kernels/split.rs:1450-1457`). Phase 12 (spike-024) made the
production default path the SIBLING CO-PACK function
`find_best_splits_fused_siblings_from_handles_on` (split.rs:1584-1767), which has **NO drain
block**. So on the production path the drain never fires — spike-034 saw it inert.

(Secondary: the drain is gated `_scan_prof && scan_drain_enabled()` = `LGBM_SCAN_PROF=1` AND
`LGBM_SCAN_DRAIN=1`, and the re-attribution is read from the SCAN_PROF counters — NOT
phase_prof's `build` timer, whose `build=0` on the resident path is expected/unrelated. The
spike-034 harness set neither `LGBM_SCAN_PROF=1` nor read `SCAN_DRAIN_NS`.)

## Goal

Restore the build-drain on the co-pack path so build-vs-scan attribution works again, behavior-
neutral (env-gated, parity-neutral), bit-exact gate green.

## Tasks

### Task 1 — Add the drain block to the co-pack siblings scan
- **files:** `crates/lgbm-compute/src/kernels/split.rs`
- **action:** In `find_best_splits_fused_siblings_from_handles_on`, immediately BEFORE the scan
  kernel launch (after the input handles/uploads are prepared, mirroring the single-leaf block
  at :1450-1457), add:
  ```rust
  // spike-015 DIAGNOSTIC (LGBM_SCAN_DRAIN=1) — co-pack analog (quick-260625-tw1): drain
  // BOTH sibling resident histogram handles before the scan launch so each child's async
  // f32-atomic build is attributed to SCAN_DRAIN_NS, not the scan readback. Phase-12 co-pack
  // bypassed the single-leaf drain (split.rs:1450); this restores it on the production path.
  if _scan_prof && crate::fusion_prof::scan_drain_enabled() {
      let t_drain = std::time::Instant::now();
      let _ = client.read_one_unchecked(<smaller hist handle>.clone());
      let _ = client.read_one_unchecked(<larger  hist handle>.clone());
      crate::fusion_prof::SCAN_DRAIN_NS.fetch_add(
          t_drain.elapsed().as_nanos() as u64,
          std::sync::atomic::Ordering::Relaxed,
      );
  }
  ```
  Use the actual handle bindings the function holds for the two slots (read the fn body to get
  the exact names; both are the per-sibling resident histogram device Handles). Ensure
  `_scan_prof` (= `crate::fusion_prof::scan_enabled()`) is bound in the fn the same way the
  single-leaf path binds it at :1342 — add the binding if absent. Drain BEFORE the launch
  timer starts (so the launch+readback timer stays pure scan).
- **verify:** `cargo build --features rocm` compiles; the block is gated (inert when either env
  is off).
- **done:** the co-pack siblings fn has the drain block, gated identically to the single-leaf path.

### Task 2 — Bit-exact gate (behavior-neutral confirmation)
- **files:** none (test only)
- **action:** `cargo test -p lgbm-treelearner --lib` and `cargo test -p oracle-harness` (the

- **verify:** both suites green (same as pre-change).
- **done:** bit-exact gate green.

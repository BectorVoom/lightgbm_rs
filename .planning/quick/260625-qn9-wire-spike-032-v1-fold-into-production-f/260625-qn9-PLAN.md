<objective>
Wire spike-032 V1 fold into production: eliminate the redundant validation random-gather in
`DataPartition::split_fused_host` by merging the per-row bin range-check INTO pass-1's route
gather. Currently the function does TWO random gathers over the leaf's scattered rows (a
standalone validation loop, then pass-1 route+count); the fold collapses these to ONE gather
plus a per-row branch.

Spike-032 (VALIDATED, 3 restarts, parity OK every cell) measured this fold at ~1.14-1.41x at
production U8 width / up to ~1.8x at U32, bit-exact on BOTH the success path (identical
[left|right]) AND the error path (same lowest-index offender, no `indices` mutation).

Purpose: reclaim a few-percent on the campaign's #1 CPU-vs-C++ residual (single-threaded
`DataPartition::split`, ~29% of tall-narrow train) on the "cut TRAFFIC, not add cores" lever —
a FREE, bit-exact win.
Output: a folded `split_fused_host` in `crates/lgbm-treelearner/src/data_partition.rs`.
</objective>

  <action>
In `split_fused_host` (currently ~lines 206-298), apply the spike-032 V1 fold. The exact
validated reference is `v1_fold` in
`crates/lgbm-compute/examples/spike032_partition_validation_fold_ab.rs` (lines 121-161) — match
its merged-loop body.

KEEP UNCHANGED (do not touch):
- The `num_bin == 0` pre-check returning `ComputeError::Runtime`.
- The `threshold >= num_bin` pre-check returning `ComputeError::Runtime`.
- The router setup block (`min_b`/`max_b`/`thr`/`th`/`default_to_right`/`go_right` closure).
- Pass 2 (the scatter into `out` + `copy_from_slice` back into the leaf slice) and the
  `left_count`/`right_count` return.

DELETE the standalone per-row validation loop (currently ~lines 230-246, the `for i in 0..count`
that reads `feature_bins.bin(row)`, checks `b >= num_bin`, and returns
`ComputeError::BinIndexOutOfRange`). Also remove its now-stale leading explanatory comment block
about the per-row bin range check (the ascending-leaf-position note ~lines 230-235).

MERGE the range-check into the pass-1 route+count loop (currently ~lines 268-275). The folded
pass-1 loop body, per row `i`, must: read `let row = self.indices[begin + i];`; gather the bin
ONCE into a local `let b = feature_bins.bin(row as usize);`; range-check BEFORE writing anything —
`if b >= num_bin { return Err(ComputeError::BinIndexOutOfRange { row: i, bin: b, num_bin }); }`;
then `let gr = go_right(b);`; then `route[i] = gr as u8;`; then `left_count += (!gr) as usize;`.

Critical correctness invariants (these are WHY the fold is bit-exact — preserve them exactly):
- The range-check `return Err(..)` must occur BEFORE any write to `route` (and before the pass-2
  scatter), so an early-return on the first bad bin leaves `self.indices` UNMUTATED — the same
  no-mutation guarantee as the deleted standalone loop. Pass-1 only writes the local `route`
  scratch and `left_count`, never `self.indices`, so this holds.
- The loop must iterate in ASCENDING leaf position (`for i in 0..count`), so the FIRST offender
  encountered is the LOWEST-index one — the same `BinIndexOutOfRange { row: i, .. }` the V0 code
  surfaced.
- Note the `go_right` closure currently takes `b: u32` and internally does `b as i32`; pass the
  already-gathered `b` to it (do NOT re-call `feature_bins.bin(row)` — that would reintroduce the
  redundant gather).

Update the doc comment on `split_fused_host` (the `///` block ~lines 197-205) to note the
range-check is now folded into the single pass-1 gather (spike-032 V1), removing any wording that
implies a separate validation pass.
  </action>

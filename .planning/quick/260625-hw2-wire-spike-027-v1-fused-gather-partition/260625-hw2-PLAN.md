<objective>
Wire spike-027 V1 (fused-gather, u8 route scratch) into the production
`DataPartition::split` numeric branch — CPU-path ONLY, bit-exact — replacing the
current materialize-then-op path (leaf_rows.to_vec() + u32-widened
leaf_feature_bins + backend.data_partition local-index reorder + local→row
remap). The RocmBackend numeric branch keeps routing on-device unchanged.

Spike-027 is VALIDATED + bit-exact (2 process restarts), 1.3–2.7× faster — the
biggest win at the production narrow-bin (U8) case. The partition residual is
~29% of tall-narrow CPU train and the #1 remaining CPU-vs-C++ gap.

Purpose: cut partition memory traffic (~4 count-u32 buffers → ~1 gather + ¼-width
u8 route + 1 u32 out) without any change to the stable [left|right] order, the
V5 bounds validation behavior, the (left_count,right_count) return, or the
leaf bookkeeping.
Output: a `prefers_host_partition()` backend discriminator + a fused host split
path gated on it + a byte-identity unit test.
</objective>

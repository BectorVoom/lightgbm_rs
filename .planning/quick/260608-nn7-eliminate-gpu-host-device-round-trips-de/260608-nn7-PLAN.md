<objective>
Eliminate GPU host↔device round-trips (staging overhead) by keeping data device-resident instead of bouncing through the host every leaf. This is a GPU-only (`RocmBackend`) optimization on the gfx1100; the CPU path (the bit-exact merge gate) is NOT touched.

Two staged wins land here:
- **L1 — device-resident binned dataset:** upload the binned feature matrix to the GPU ONCE per train (cache the cubecl `Handle`s in `RocmBackend` via interior mutability), and gather leaf rows ON DEVICE by uploading only the small `leaf_rows` index array per leaf — instead of host-gathering `gathered_bins [num_features × rows]` and re-uploading it every leaf (`build_leaf_histograms_batched_f32_on`, histogram.rs:441-496).
- **L2 — residency through scan:** keep the per-leaf RAW histogram device-resident from the build kernel's output straight into the split-scan kernel, so `find_best_splits_batched` no longer re-uploads a host hist buffer on the GPU path.

Purpose: removes the two largest repeated host↔device transfers in the per-leaf flow (the per-leaf bins re-upload, and the build→read→scan-reupload hist bounce). NO GPU baseline exists anywhere — the plan captures GPU before/after numbers to prove the win.

Output: an interior-mutable `RocmBackend` device-state, device-resident-bins + resident-hist seams (with CpuBackend defaults = today's exact host behavior), the GPU launchers, and a measured GPU bench.

**L3 (on-GPU FixHistogram + compaction) is EXPLICITLY DEFERRED to a follow-up** — see `<deferred_scope>`. It is the riskiest part (subtle most_freq_bin compaction semantics, DEF-07-02 class) and L1+L2 already remove the two dominant round-trips. Shipping L1+L2 solidly + measured beats over-stuffing this task.
</objective>

## DEFERRED to a follow-up quick task: L3 — on-GPU FixHistogram + compaction

**Why deferred:** L3 is the riskiest part. FixHistogram (`fix_histogram.rs`, the most_freq_bin reconstruction) and `compact_histogram` (learner.rs:2826, the offset==1 bin-0-drop shift) have SUBTLE integer/index semantics (DEF-07-02 histogram-compaction divergence class; na/default-bin handling). Moving them onto the GPU is RocmBackend-only and must reproduce the host result within ~1e-6 in f32 accumulation AND match the host integer/index behavior EXACTLY. Until L3 lands, the per-leaf flow still does ONE host read-back of the RAW hist (so the host can fix+compact) — that read-back is the round-trip L3 owns.

**What L3 must do (for the follow-up plan):**
- Add an on-GPU FixHistogram+compaction kernel (RocmBackend-only) that consumes the resident RAW hist `Handle` (from Task 1's build kernel) and produces the fixed+compacted resident buffer the scan consumes — so the build→fix→scan chain never touches the host.
- Gate HARD on the ~1e-6 parity PLUS an oracle assertion that GPU-fixed == host-fixed within tolerance, with explicit coverage of most_freq_bin>0 (FixHistogram active) and offset==1 (compaction active) cases. If parity cannot be held, STOP and report — do NOT weaken any tolerance.
- Keep the host FixHistogram/compaction code intact for CpuBackend (the merge gate).

L1+L2 already remove the two dominant repeated transfers (the per-leaf bins re-upload and the redundant scan plumbing); L3 closes the final fix-mandated read-back. Shipping L1+L2 first delivers the bulk of the win at lower risk.

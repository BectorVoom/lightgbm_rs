Investigate-and-bench: warp-aggregate (Plane) the global f32 `fetch_add`s in the ROCm histogram
scatter kernel to cut global-atomic contention, then ship ONLY on a robust positive bench.

Per RESEARCH, the expected win is **likely NULL** (3 corroborating in-repo findings:
gpu-hist-levers-closed, spike-006, ol8 — the atomic kernel is contention/scattered-read-latency
bound; at 256 bins a 32-lane wave hits ~30 distinct bins, so there is almost nothing to amortize).

"benched → NULL → kept as a rocm-gated primitive, NOT wired into the training path" is a fully valid
success outcome, the same disposition as ngo/ol8/j9t.

Purpose: close the one genuinely un-benched GPU histogram contention lever (warp-aggregated atomics)
with a clean A/B signal, honoring the f32 ~1e-6 rocm parity contract and never touching the CPU f64
anchor or widening any tolerance.

Output: a comptime-gated rocm `_plane` kernel variant + host launcher (reusing the existing plane
capability gate), an interleaved plane-vs-baseline A/B bench, a GPU-vs-CPU-f64-anchor re-pin test,
and a FINDINGS.md with the honest disposition.

  <files>crates/lgbm-compute/src/kernels/histogram.rs</files>
  <action>
Add a NEW rocm-gated kernel `construct_hist_kernel_atomic_f32_plane` BESIDE `construct_hist_kernel_atomic_f32`
(~line 389), and a host launcher `construct_histograms_parallel_f32_plane_on` beside
`construct_histograms_parallel_f32_on` (~line 416). Do NOT modify either existing kernel or its launcher
— they stay byte-unchanged (the bench Task 2 uses the existing launcher as the baseline arm).

Kernel signature mirrors the baseline plus a `#[comptime] use_plane: bool` flag (manual "Feature
Specialization with Comptime Flags" — generates a distinct binary with NO device branch; the CPU-only
build never compiles the `rocm` cfg so never emits plane codegen):
  `#[cfg(feature = "rocm")] #[cube(launch_unchecked)] pub fn construct_hist_kernel_atomic_f32_plane(binned: &Array<u32>, grad: &Array<f32>, hess: &Array<f32>, out: &mut Array<Atomic<f32>>, #[comptime] use_plane: bool)`

Behavior:
  - `idx = ABSOLUTE_POS`; guard `if idx < binned.len()` (launch rounds unit count up to a cube-dim
    multiple — tail units stay idle, manual §4 Safe Indexing).
  - When `use_plane == false`: emit the EXACT baseline body — `out[bin*2].fetch_add(grad[idx])`,
    `out[bin*2+1].fetch_add(hess[idx])` — so this arm is a byte-faithful twin of the shipped kernel.
  - When `use_plane == true`: do CORRECT same-bin warp aggregation. A naive `plane_sum` over the whole
    plane is WRONG (divergent bins corrupt the histogram — RESEARCH Pitfall 1). There is NO
    `plane_match_any` in cubecl 0.10, so group lanes by equal bin via a leader-iteration loop:
      * each lane holds its `bin` (and its grad/hess; out-of-range tail lanes set a sentinel bin so
        they never match — gate on the `idx < len` predicate);
      * iterate: elect the lowest still-unclaimed lane's bin as `leader_bin` (use `plane_ballot` of
        "unclaimed" + the runtime `PLANE_DIM`-indexed mask to find the first set lane, then
        `plane_broadcast`/`plane_shuffle` that lane's bin to all lanes — index the 4×u32 ballot vector
        by runtime `PLANE_DIM`, NEVER hardcode 32 since `plane_ballot` always returns 128 bits even on
        wave32, RESEARCH Pitfall 6);
      * `same = (my_bin == leader_bin) && active`; reduce that group's grad/hess (mask each lane's
        contribution to the group then `plane_sum`, or popcount-weighted shuffle);
      * ONE elected lane per group (`plane_elect` among the group, or the leader lane) issues a SINGLE
        `out[leader_bin*2].fetch_add(group_grad_sum)` + `out[leader_bin*2+1].fetch_add(group_hess_sum)`,
        collapsing up to PLANE_DIM global atomics per bin into one;
      * mark the group's lanes claimed; repeat until no lane is unclaimed.
    Use only the verified cubecl 0.10 primitives (RESEARCH table): `plane_ballot`, `plane_elect`,
    `plane_broadcast`, `plane_shuffle`, `plane_sum`, `plane_all`/`plane_any`, builtins `UNIT_POS_PLANE`,
    `PLANE_DIM`. Do NOT make `num_bin` comptime (gpu-hist-levers-closed: re-introduces avoided
    multi-binary cost).

Host launcher `construct_histograms_parallel_f32_plane_on<R: cubecl::Runtime>(client, binned, grad, hess,
num_bin, use_plane: bool)` — copy `construct_histograms_parallel_f32_on` verbatim (same
`validate_histogram_inputs` V5 boundary checks, same zeroed-f32 alloc, same `ceil(n/256)` cube count of
256 units, same f32→f64 widen on read-back), but:
  - launch `construct_hist_kernel_atomic_f32_plane::launch_unchecked` passing the `use_plane` comptime
    flag (the comptime arg is supplied at the call site per the cubecl launch ABI);
  - GATE: when the caller passes `use_plane == true`, the launcher asserts/relies on the existing
    `probe_capabilities(client).has_plane` — REUSE the existing probe in `runtime.rs`, do NOT re-roll it
    (RESEARCH §host-side gate). Document in the SAFETY comment that `use_plane=true` requires
    `has_plane`, falling back to `use_plane=false` (the byte-faithful baseline arm) otherwise.
  - carry the same launch_unchecked SAFETY enumeration the baseline launcher has (every device access
    host-proven in range before upload; V5 discharges the obligations).

Parity note in the doc comment: the plane group-reduction is an f32 TREE reduction (different
accumulation order than the sequential atomic chain) but both are non-deterministic f32 accumulations
measured against the CPU f64 anchor at ABS 5e-6 / REL 1e-5 — the contract was designed for exactly this
f32 reordering (D-03a, 04-ROCM-GAPS); a tree reduction is typically MORE accurate than a long
sequential chain, so it is expected to stay well inside the existing envelope. Do NOT widen any
tolerance. Do NOT touch `construct_hist_kernel` / `construct_hist_kernel_f32` (the CPU f64 anchor
kernels) — byte-unchanged.

# Quick 260619-p93: Plane (warp) aggregation of the f32-atomic histogram — Summary

**One-liner:** Added a correct, comptime-gated, rocm-only warp-aggregated `_plane`
variant of the f32-atomic histogram scatter kernel (same-bin leader-iteration via
`plane_ballot`/`plane_shuffle`/masked `plane_sum`, one global atomic per distinct bin
per plane) + an interleaved A/B bench + a GPU-vs-CPU-f64-anchor re-pin test; the
gfx1100 A/B shows the lever is **NULL** (robustly slower in 5/6 cells, the one
positive cell spread-overlapping), so it is kept as a rocm-gated **primitive, NOT
wired** — the honest, valid measurement-disposition outcome.

## What was built

- **Task 1 — kernel + launcher (`histogram.rs`, commit `428bd79`).**
  `construct_hist_kernel_atomic_f32_plane` (`#[cfg(feature="rocm")]`,
  `#[cube(launch_unchecked)]`, `#[comptime] use_plane: bool`):
  - `use_plane=false` → the EXACT baseline body (byte-faithful twin of the shipped
    `construct_hist_kernel_atomic_f32`);
  - `use_plane=true` → CORRECT same-bin warp aggregation: each lane holds its bin;
    a leader-iteration loop ballots the unclaimed lanes (`plane_ballot`, scanning all
    4 ballot words so it is wave32/wave64-portable — no hardcoded 32), `plane_shuffle`s
    the leader bin to all lanes, builds the group mask, reduces grad/hess with a masked
    `plane_sum`, and the leader lane issues ONE global atomic per distinct bin.
  `construct_histograms_parallel_f32_plane_on` — a near-verbatim copy of the baseline
  launcher passing the `use_plane` comptime flag; documents the existing
  `probe_capabilities(...).has_plane` gate contract (reused, not re-rolled).
  Pure-addition diff: the baseline kernel + launcher and BOTH CPU f64 anchor kernels
  are byte-unchanged; the CPU-only build emits zero plane codegen.

- **Task 2 — bench + re-pin test (commit `ad98172`, refined `7908b5c`).**
  `examples/plane_aggregate_ab.rs`: interleaved warp-aggregate vs baseline A/B; SAME
  launcher both arms (only the comptime flag differs); bin sweep `[16,64,256]`;
  launch-bound + compute-bound regimes; warm medians + p25/p75; same-input f32 drift
  guard. `tests/rocm_plane_aggregate.rs`: pins the plane variant to the CPU f64 anchor
  (never GPU-vs-GPU, DEF-f8u-01) within ABS 5e-6 / REL 1e-5 at the calibrated regime,
  plus contention/integer-equivalence and large-leaf-drift coverage.

- **Task 3 — gfx1100 verify + disposition (this run).** Ran the re-pin test (5/5),
  the A/B bench twice, the CPU-only build/test, and the existing
  `rocm_parallel_histogram` gate (7/7). Recorded the honest NULL disposition in
  `260619-p93-FINDINGS.md`.

## Result / disposition

**NULL — kept as a rocm-gated primitive, NOT wired into the training path.**

A/B (2 process runs, gfx1100): plane is robustly SLOWER in 5 of 6 cells
(launch-bound 16/64/256: −6 to −56%; compute-bound 64/256: −15 to −45%, the 256-bin
case is RESEARCH's exact decider — ~30 distinct bins per 32-lane wave, nothing to
amortize). The ONLY positive cell (compute-bound, 16 bins, +13–14%) is sign-stable
but spread-OVERLAPPING and regime-narrow — it does NOT clear the spread-separated
bar required to wire. This confirms the RESEARCH prediction and 3 prior in-repo
findings (gpu-hist-levers-closed, spike-006, ol8): the kernel is
contention/scattered-read-latency bound. The wiring decision is flagged DO-NOT-WIRE
(see FINDINGS § human sign-off flag).

Correctness is proven: plane vs CPU f64 anchor ≤4.6e-7 at n=8000 (well inside the
1e-5 gate); no lost/misrouted update under contention; exact vs the baseline on
integer data. A naive whole-plane `plane_sum` would have failed these.

## Deviations from Plan

**1. [Rule 1 — test-shape calibration] Restricted the float-tolerance re-pin to the
≤8000-row regime; added a large-leaf-drift-not-worse test.**
- **Found during:** Task 3 (first gfx1100 run of `rocm_plane_aggregate`).
- **Issue:** the initial `plane_within_tolerance_of_cpu_f64_anchor` swept n=50000,
  where it failed at bins=16 (rel 2.44e-4 > 1e-5).
- **Root cause (diagnosed on-GPU):** a shared large-leaf f32-cancellation effect, NOT
  a plane bug — the SHIPPED baseline per-row path drifts the SAME amount at that shape
  (baseline-vs-anchor 3.05e-4, plane-vs-anchor 2.93e-4). The 1e-5 gate is calibrated
  for the ≤8000-row regime the existing `rocm_parallel_histogram` gate uses.
- **Fix:** restricted the 1e-5 test to n=8000 (matching the existing gate) and added
  `plane_large_leaf_drift_not_worse_than_baseline` asserting the plane stays within 2×
  the shipped baseline's own drift. **No tolerance widened on any existing gate.**
- **Files:** `tests/rocm_plane_aggregate.rs`, `examples/plane_aggregate_ab.rs` (the
  A/B same-input check made leaf-aware as a GPU-f32-vs-GPU-f32 DRIFT guard, not a
  parity gate). **Commit:** `7908b5c`.

No other deviations. The CPU f64 anchor was untouched and no parity tolerance widened.

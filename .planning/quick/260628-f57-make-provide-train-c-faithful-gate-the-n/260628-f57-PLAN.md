# Quick 260628-f57: make `provide_train` C++-faithful

## Why
Spike-048 attributed ~26% of lightgbm_rs's CUDA wall (4.49s of 17.04s at 500k×50)
to per-iteration training-metric eval that official LightGBM skips. Root cause
`booster.rs:1291`:
```rust
let provide_train = config.is_provide_training_metric || valid.is_none();
```
The `|| valid.is_none()` clause forces training-metric eval whenever there is no
`eval_set` — divergent from C++ (default `is_provide_training_metric=false` ⇒ no
training metric ⇒ empty `evals_result_`). Proven on Kaggle: dropping the per-iter
eval saves ~23% wall, parity-neutral to the trees.

## What (C++-faithful, test-first)

### Task 1 — Core fix
`crates/lgbm/src/booster.rs:1290-1291`: change `provide_train` to
`config.is_provide_training_metric` (drop `|| valid.is_none()`); update the comment.

### Task 2 — Realign the deliberately-divergent call sites
Several sites train WITHOUT a valid set and read training-metric `eval_history`,
relying on the old clause. They must opt in explicitly via
`.is_provide_training_metric(true)` (Rust API) — this is the correct C++ alias and
preserves their intent. Drive by `cargo test` failures, not by guessing:
- `crates/lgbm/src/booster.rs` unit tests: `public_api_train_predict_round_trip`,
  the custom-metric eval_history test, `metric_freq_thins_eval_history`, and any
  other no-valid test asserting training history.
- `crates/oracle-harness/tests/boosting_parity.rs`: `multiclass_cell_builder`
  (feeds `train_multiclass` + `train_multiclassova` → `assert_multi_logloss`). The
  goldens (`multiclass_metrics.txt`, `multiclassova_metrics.txt`) ALREADY contain
  per-round training `multi_logloss`, so adding the opt-in makes the Rust config
  match how the capture was generated — **parity preserved, not changed.**

### Task 3 — Verify
- `cargo test -p lgbm` green.
- `cargo test -p oracle-harness multiclass` (the parity cells touching training
  metrics) green.
- Confirm no NEW behavior for the valid-set path (valid metrics + ES untouched —
  only the no-valid training-metric default changes).

## must_haves
- truths:
  - With no eval_set and default config, `train()` no longer computes a per-iter
    training metric (matches C++; `eval_history` empty).
  - With `.is_provide_training_metric(true)`, training-metric history is produced
    exactly as before.
- artifacts:
  - `crates/lgbm/src/booster.rs` (provide_train + test opt-ins)
  - `crates/oracle-harness/tests/boosting_parity.rs` (multiclass opt-in)
- key_links:
  - booster.rs:1291 (the divergent clause)

## Notes / caveats
- Python sklearn path: training without `eval_set` now yields empty `evals_result_`,
  matching official `lightgbm`. No Python source change needed; wheel rebuild not run
  here (heavy) — flagged for the Python test suite as a follow-up if any test
  asserted non-empty training history without eval_set.
- Parity is the project hard gate: the harness change only adds the explicit opt-in
  so the Rust side keeps reproducing the (unchanged) goldens.

<objective>
Add a fused per-feature GPU kernel — one cube per feature, single-owner sequential
f64 — that collapses build (gather leaf rows → ascending f64 fold) → FixHistogram →
compact → best-split scan → emit that feature's SplitInfo into ONE launch, on the
launch-bound directly-built-leaf path. This collapses today's construct + folded-fix
+ scan = 3 launches into 1 for directly-built leaves (root + smaller children).

Purpose: the s2b profile found the GPU path is launch-bound (~205 launches/tree, pool
already hits). Fusing the directly-built-leaf chain attacks launch count directly.
Size-gated: small/medium (launch-bound, few rows ⇒ sequential f64 fold is cheap) use
the fused kernel; large keeps the atomic-parallel resident path (sequential f64 over
20k rows would be slow).

Output: a new `#[cube(launch)]` kernel + host launcher (GPU-only), a Backend seam
(no-op/error default ⇒ CpuBackend byte-unchanged), a fused==host bit-exact oracle,
wiring for directly-built leaves on the eligible small/medium path, and BEFORE/AFTER
bench numbers with an HONEST net-win report.

HONEST EXPECTED-WIN BOUND (reason from code, re-measure to confirm): directly-built
leaves ≈ root + smaller children ≈ ~half of a num_leaves=31 tree (~16 leaves/tree).
Each currently costs construct(1) + folded-fix(1) + scan(1) = 3 launches; fused = 1.
That saves ~2 launches × ~16 leaves ≈ ~32 launches/tree out of ~205 ≈ ~15%. BUT this
only applies on the small/medium SIZE-GATED path, where s2b measured the resident
chain currently LOSES to the host path (host 1.50/4.33s vs resident 1.64/4.68s at
2k/8k). So the open question this plan answers empirically: does the fused
single-launch kernel beat BOTH the 3-launch resident chain AND the host path on
small/medium? If the fused kernel does not beat the host path on small/medium, REPORT
THE FLAT/NEGATIVE RESULT HONESTLY — this thread has had several correct-but-flat
results (kt8/lad/s2b); do NOT manufacture a win. Worst-case honest outcome: a proven
bit-exact fused kernel that is correct, launch-reducing, but net-flat at small/medium,
landed behind the size gate set to whatever the bench says wins.
</objective>

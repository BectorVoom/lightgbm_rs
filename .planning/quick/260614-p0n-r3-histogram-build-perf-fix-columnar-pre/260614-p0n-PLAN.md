<objective>
Cut the CPU histogram-construction cost that dominates low-row training (spike 002:
build = 232µs/iter vs C++ 44.5µs/iter, 5.2×, ≈187µs of the ~188µs/iter total gap),
while holding the project's BIT-EXACT CPU f64 merge gate.

Spike 002 localized the gap to allocation/instruction churn INSIDE the histogram
build phase (callgrind: ~22% of in-main instructions are malloc/free/memset/memcpy,
NOT cache misses at 2k rows). The churn has two concrete sources, both removable
WITHOUT touching the f64 fold order:

1. `construct_histograms_cpu_native` allocates + zeroes a fresh `vec![0.0f64; 2*num_bin]`
   per FEATURE per LEAF, folds into it, then copies it into the caller's `out` buffer.
   That is one alloc + one memset + one memcpy per feature per leaf.
2. `build_leaf_histogram_into` (the learner) allocates `feature_bins` and `num_bins`
   descriptor Vecs per call; the native `build_leaf_histograms_raw` allocates `out` +
   the `ord_bins/ord_g/ord_h` gather Vecs per leaf call.

This plan removes (1) with a fold-in-place accumulator that writes directly into the
caller's pre-zeroed `out` sub-slice (identical rows, identical ascending order,
identical `bin<<1` cell layout, identical f32-read/f64-accumulate ⇒ identical bits),
and removes the per-call descriptor allocation in (2) by reusing learner-held scratch
across iterations. The gather buffers (`ord_*`) are already reused across features
within one leaf today; this plan does NOT need a full columnar storage rewrite — the
in-place fold subsumes the dominant per-feature alloc churn (the spike explicitly
authorizes scoping to the highest-ROI, lowest-risk subset and deferring the rest).

Purpose: close the dominant low-row CPU perf gap on the native f64 anchor path.
Output: a fold-in-place native accumulator + reused learner scratch, measured
before→after with the phase profiler, bit-exact preserved.

SCOPE GUARD (non-negotiable):
- Native CPU f64 path ONLY. GPU/ROCm/cubecl kernels are OUT OF SCOPE (separate ~1e-6
  track) — do NOT touch `construct_hist_kernel*`, the rocm-gated atomic builds, the
  resident/fused device chain, or the RocmBackend `build_leaf_histograms_raw` override.
- Do NOT touch the split scan or the partition phase (both near parity, 1.4×/2.1×).
- The f64 fold ORDER is FROZEN. Same order in = same bits out. Any change that cannot
  guarantee identical fold order is REJECTED.
</objective>

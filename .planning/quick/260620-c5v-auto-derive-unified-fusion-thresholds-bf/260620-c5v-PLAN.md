<objective>
Auto-derive the two unified-fusion gate thresholds from CPU core count, replacing the
hand-tuned constants (bfs=100, subscan=130) that were measured only at THIS machine's
16 cores (quick a48 / b97). The thresholds gate `features.len() >= threshold()` — the
feature count at which one rayon fork/join's overhead is amortized by the parallel
build/scan work across features. That break-even depends on core count, so a constant
measured at 16 cores is wrong on other machines.

The honest scope is MEASURE FIRST: the theoretical model `T(P) = (O/c)·P/(P−1)` predicts
T decreases mildly with more cores, but O (sync overhead) likely grows with P and partially
offsets — so the real T-vs-cores curve MUST be measured on this box (by sweeping
RAYON_NUM_THREADS), not assumed. If the curve is materially core-dependent → ship a
clamped core-scaled formula (WIN). If it is roughly flat across 2–16 cores → ship a MINIMAL
change (keep ~100/130 with a light extreme-core clamp) and document that auto-derivation
buys little (NULL). Faithfulness over busy-work.

Purpose: make the fusion-gate defaults portable across machines without regressing this box.
Output: edited crates/lgbm-compute/src/lib.rs (both threshold fns + a helper), plus a
measured T-vs-cores table recorded in the SUMMARY.
</objective>

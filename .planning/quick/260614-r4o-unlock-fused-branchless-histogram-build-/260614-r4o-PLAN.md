<objective>
Unlock spike 003b's fused branchless histogram build by RELOCATING the per-element
bin-range validation (V5 / threat T-04-01) out of the hot fold. Spike 003b proved the
fused build (folding directly from the bin column into a reused per-feature hot scratch,
no ord_bins materialization, no per-feature alloc) wins -17% small / -4.5% large AND is
bit-exact — but ONLY if the fold is BRANCHLESS. Any per-element `bin < num_bin` check
serializes the loop and regresses large ~3-8%. The fix: trust the bin-range invariant in
the hot fold (matching C++ `dense_bin.hpp`, which folds `data_[i]` with no per-element
check), validated ONCE per train upstream + a `debug_assert!`.

Purpose: close the remaining histogram-build headroom (build is still 52.9% small /
90.2% large of train after spike-003) at zero parity cost — the R3 lever.

  RELOCATION (not removal).

Reproduce spike 003b's fused branchless build in the DEFAULT `Backend::build_leaf_histograms_raw` (lib.rs ~205). KEEP spike-003's once-per-leaf ord_g/ord_h gather (the `for &row in leaf_rows { ord_g.push(gradients[row]); ord_h.push(hessians[row]); }` block before the feature loop — values+order unchanged). REPLACE the per-feature `ord_bins` re-gather + `self.construct_histograms(...)` call with a fused branchless fold:

  - Allocate ONE reused per-feature hot scratch sized to the widest feature: `let max_cells = num_bins.iter().copied().max().map_or(0, |m| 2 * m as usize); let mut scratch = vec![0.0f64; max_cells];` (this is the <= 2*max_num_bin hot scratch — NOT the big multi-feature `out` buffer; p0n proved folding into `out` regresses large ~9%).
  - For each feature `fpos`: let `cells = 2 * num_bins[fpos] as usize`; zero `scratch[..cells]` (`for c in scratch[..cells].iter_mut() { *c = 0.0; }`); then fold the leaf's rows DIRECTLY from the bin column in ASCENDING `leaf_rows` order with NO per-element bin check:
        for (k, &row) in leaf_rows.iter().enumerate() {
            let bin = bins[row as usize];
            debug_assert!(bin < num_bins[fpos], "bin {bin} >= num_bin {} — caller must establish the bin-range invariant once per train (T-04-01 relocation)", num_bins[fpos]);
            let ti = bin as usize * 2;
            scratch[ti]     += f64::from(ord_g[k]);
            scratch[ti + 1] += f64::from(ord_h[k]);
        }
    Then stream-copy: `out[slot_off[fpos]..slot_off[fpos] + cells].copy_from_slice(&scratch[..cells]);`

  CRITICAL fold-order fidelity (the bit-exact gate depends on it): rows iterate in ASCENDING `leaf_rows` order; grad cell at `bin<<1`, hess at `+1`; `f32`-read -> `f64`-accumulate via `f64::from(...)`. This is byte-identical math to `construct_histograms_cpu_native` (histogram.rs:209-235) — the ONLY change is reading `bins[row]` inline instead of materializing `ord_bins`. Do NOT reorder, do NOT batch, do NOT add a clamp/OOB-flag branch (003b proved both the early-return branch AND the branchless clamp+OR regress large).

  Update the doc comment on `build_leaf_histograms_raw`: state that bin-range validity (every `bins[row] < num_bins[fpos]`) is now a CALLER-GUARANTEED PRECONDITION established ONCE per train by the upstream check in `lgbm-treelearner` `train_inner` (cite it by name), mirroring C++ `dense_bin.hpp` which folds `data_[i]` with no per-element check. The `# Errors` section: the fused fold no longer returns `BinIndexOutOfRange` per element (it cannot — there is no per-element check); document the `debug_assert!` as the debug/test defense-in-depth and the upstream check as the production guarantee. Keep returning `Result` (the signature is unchanged); the body now has no fallible per-feature call, so wrap the final value in `Ok(...)` — if a `Result` is still required by the trait signature, return `Ok(out)`.

  Do NOT touch the `RocmBackend` override (lib.rs:854) or any GPU/cubecl/rocm code.

# PLAN: O1+O2 column-major `RawCorpus`

## Goal
Store `RawCorpus` feature values **column-major in a single flat `Vec<f64>`** so:
- **O1:** the polars/Arrow ingest writes columns directly (no col→row transpose) and
  binning reads each column directly (no row→col transpose) — the double transpose dies.
- **O2:** one contiguous allocation (was `num_rows` nested `Vec`s); binning reads each
  feature as a contiguous `&[f64]` slice (no per-column gather).

**Parity contract:** value-preserving reordering only. Each feature column feeds
`find_bin_*` the IDENTICAL f64 values in the IDENTICAL row order → bit-exact gate
must stay GREEN. `DenseCorpus` (identity-binned spine) is UNTOUCHED.

## Representation
```rust
pub struct RawCorpus {
    col_major: Vec<f64>,   // value(row,col) = col_major[col*num_rows + row]; private
    num_rows: usize,       // private
    num_cols: usize,       // private
    pub labels: Vec<f32>,
    pub categorical_features: Vec<usize>,
    pub config: Config,
}
```
- `new(rows: Vec<Vec<f64>>, labels)` — row-major in (numpy/CSR/CSC + tests); transposes once.
  Ragged input ⇒ leaves `col_major` empty so the `col_major.len() == num_rows*num_cols`
  invariant fails (preserves the ragged→`InvalidCorpus` test contract; no panic).
- `from_columns(columns: Vec<Vec<f64>>, labels)` — column-major in (polars/Arrow); stores
  verbatim (O1, no transpose).
- `num_data()`, `num_features()`, `column(j) -> &[f64]` (contiguous, O2), `value(r,c)`,
  `to_rows() -> Vec<Vec<f64>>` (on-demand row-major for predict-style consumers only).

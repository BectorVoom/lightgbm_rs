<objective>
Port LightGBM's CUDA single-GPU histogram-construction kernel
(`CUDAConstructHistogramDenseKernel`, the signature inner kernel of
`cuda_single_gpu_tree_learner`) to a faithful CubeCL `#[cube(launch)]` kernel that
runs on the local AMD gfx1100 via cubecl-hip, and benchmark the GPU whole-tree-learner
loop against the current CPU path on an identical corpus.

Per the user's two decisions: (1) interpretation = a CubeCL kernel mirroring the CUDA
*algorithm* (raw `.cu` is out — violates the no-raw-CUDA constraint and won't run on
AMD); (2) target = the whole tree-learner loop (histogram + split + partition).

Critical codebase reality (already verified): the whole tree-learner loop ALREADY runs
end-to-end on rocm — `lgbm::train(&cfg, &corpus)` compiled `--features rocm` swaps in
`RocmBackend`, which drives a per-leaf build→subtract→split→partition chain mirroring
`cuda_single_gpu_tree_learner`'s per-leaf loop. The histogram, split, and partition
kernels all already have CubeCL ports. Do NOT rewrite them.

The TWO genuine gaps this plan closes:
  (A) The currently-wired histogram path (`construct_histograms_parallel_f32_on` /
      `construct_leaf_hist_batched_lds_kernel`) does NOT mirror the CUDA kernel's
      signature structure. The CUDA kernel: gathers leaf rows via
      `data_indices_in_leaf` INSIDE the kernel from a resident column buffer; uses a 2D
      thread tile where `threadIdx.x` selects the FEATURE/column and `threadIdx.y`
      strides over rows; accumulates a multi-column per-BLOCK LDS sub-histogram with
      `atomicAdd_block`; then flushes once per cell with a single global atomic. The
      existing CubeCL kernels instead host-gather leaf rows into flat per-leaf buffers
      and use a 1D one-unit-per-(feature,row) or single-feature layout. Task 1 adds the
      faithful structural mirror as a tested primitive.
  (B) The benchmark harness (`bench_train.rs`) is CPU-only — there is no GPU-vs-current
      speed comparison. Task 2 adds one.

Purpose: deliver the user's intent (a faithful CubeCL port of the CUDA kernel + a speed
comparison) within quick-task budget, without disturbing the bit-exact CPU anchor.

Output: a rocm-gated mirror kernel + host launcher, a gfx1100 parity test pinning it to
the CPU f64 anchor at ~1e-6, and a GPU-vs-CPU whole-tree-learner benchmark example.
</objective>

    (1) gather leaf rows INDIRECTLY inside the kernel — input `data_indices: &Array<u32>`
    holds the leaf's row indices; the kernel reads `data_index = data_indices[k]` and then
    indexes a RESIDENT feature-major bin buffer `data: &Array<u32>` at
    `column_start * num_data + data_index` (mirror of `data_ptr[data_index * ncols + tx]`

    uses); grad/hess are gathered in-kernel as `grad[data_index]` (full-corpus order, NOT
    pre-gathered) — this is the signature CUDA indirection the existing kernels lack.
    (2) 2D thread tile: map `UNIT_POS_X` to the column/feature within the cube's partition
    and stride `UNIT_POS_Y` over the leaf rows (CUDA `threadIdx.x`=column, `threadIdx.y`=row);
    use CubeDim::new_2d. (3) per-CUBE LDS sub-histogram spanning ALL columns in the cube's
    partition (SharedMemory::<Atomic<f32>>::new(HIST_LDS_MAX), comptime-max-sized as the
    existing construct_hist_kernel_lds_f32 does), zero it strided, sync_cube, atomic-add
    each row's (grad,hess) into the column's LDS region at `col_hist_offset + bin*2`,
    sync_cube, then flush each active LDS cell to the global `out` with ONE fetch_add per
    cell (mirror of the `atomicAdd_block` accumulate + `atomicAdd_system` flush split).
    Reuse HIST_LDS_MAX, slot_off_sentinel, and validate_histogram_inputs from this file.

# Quick Task 260609-8go — Reuse per-iteration grad/hessian/score buffers

## Context

Source task: *"consider whether there are areas that can be optimized in arrow-rs"*, scoped (with the
user) to **lightgbm_rs**, using `/home/user/Documents/workspace/optimisor/manual` as the technique
reference, deliverable = **analysis + implement the highest-value parity-neutral win**.

### Analysis outcome (why this task)

Of the 9 manual techniques, most do **not** apply to a bit-exact-parity-gated, single-threaded-CPU-
spine LightGBM port:

| Manual technique | Verdict | Reason |
|---|---|---|
| Half precision f16/bf16 (CubeCL) | **Disqualified** | Breaks the f32-end-to-end parity contract (the project's non-negotiable). |
| Zero-copy Arrow→CubeCL upload | Low value | Project doesn't use Arrow; memory note says host↔device round-trip is **not** the GPU bottleneck. |
| bytemuck zero-copy transmutation | Low value | Same — upload path isn't the bottleneck. |
| Arrow numeric branching / dictionary casting | N/A | Arrow-specific; project has no Arrow data path. |
| compact_str (SSO) | Low value | Strings aren't in the numeric training hot path. |
| smallvec (SVO) | Partial | Real candidates exist in the tree-learner hot path, but many scratch Vecs are `num_bin`-sized (~2–4 KB) → too big for inline SVO; the truly-small ones touch the **bit-exact anchor** → parity-risky for a quick task. |
| jemalloc | Redundant | mimalloc already wired. |
| mimalloc | **Already done** | Feature-gated in the bench harness; forced-on in `lgbm-python`. Measured separately in this task. |

The genuinely-applicable, parity-neutral, *not-already-done*, *low-risk* (boosting crate, **not** the
tree-learner anchor) win is **eliminating the redundant per-iteration grad/hess/score clones in the
boosting driver**.

### Deviation from the initial premise (discovered while reading the code)

The initial framing was "reuse/pool the grad/hess/score buffers across iterations." That is **wrong**:
`Gbdt::train_one_iter` *moves* `gradients`/`hessians`/`score` out into the returned `IterSnapshot`
(`gbdt.rs:241-261`, `:908-913`), and the driver **retains every iteration's copy** in the public
golden-replay history (`Booster::iter_scores` / `iter_grad_hess`, `booster.rs:455-457`). The per-iter
values are kept for the whole run — they are **not** transient scratch, so they cannot be pooled.

The real waste is in the **caller** (`crates/lgbm/src/booster.rs:1143-1144`):
- `snap.gradients` / `snap.hessians` are **used only at the clone site** (`:1144`) → can be **moved**,
  not cloned.
- `snap.score` is **double-allocated**: `gbdt.rs:911` already does `scores().to_vec()`, then the
  caller `.clone()`s it again at `:1143` while the snapshot's own copy is dropped. Move it into
  `iter_scores` and redirect the two training-metric eval reads (`:1178`, `:1184`) to the just-pushed
  element.

Net effect per emitted iteration: **3 large allocations + memcpys removed** (grad clone + hess clone +
score clone). For the `large` bench size (20 000 rows): (80 + 80 + 160) KB = **320 KB/iter** less
alloc+copy traffic. Move == clone in data → **parity-neutral by construction**, gated by the bit-exact
oracle suite.

This change stays entirely in the boosting **driver** (`booster.rs`) and never touches
`train_one_iter` internals or the tree-learner anchor.

## Tasks

### Task 1 — Move (don't clone) the per-iteration grad/hess/score snapshots in the driver

- **files:** `crates/lgbm/src/booster.rs`
- **action:**
  - `:1144` `iter_grad_hess.push((snap.gradients.clone(), snap.hessians.clone()))` →
    `iter_grad_hess.push((snap.gradients, snap.hessians))` (move; `snap.gradients`/`snap.hessians`
    have no later use).
  - `:1143` `iter_scores.push(snap.score.clone())` → `iter_scores.push(snap.score)` (move). Bind
    `let cur_score = iter_scores.last().expect("pushed above");` immediately after.
  - `:1178` `m.eval(&snap.score, corpus_labels)` → `m.eval(cur_score, corpus_labels)`; `:1184`
    `m.resolved_name(&snap.score, corpus_labels)` → `m.resolved_name(cur_score, corpus_labels)`.
  - Confirm `cur_score`'s immutable borrow of `iter_scores` is not invalidated before the eval block
    ends (no `iter_scores` mutation in between — verified: only `valid_eval_history`/`early` are
    touched).
- **verify:** `cargo build -p lgbm` clean; touched function has no use-after-move; clippy clean on the
  loop body.
- **done:** No `.clone()` on `snap.gradients` / `snap.hessians` / `snap.score` remains in the train
  loop; the snapshot is consumed by moves.

# Quick Task 260626-a6t: Wire spike-035 (rocm host partition default-ON)

## Background

Spike-035 (VALIDATED, commit `73a2328`) showed routing the rocm partition through the SHIPPED
spike-027 fused HOST path beats the device `data_partition_native` round-trip by ~1.18–1.23× at
the launch-bound regime (medium/large), a wash at wide (no regression), and parity-safe (the
"index re-upload tradeoff" is moot — both paths land in host `indices_` and the resident build
reads host indices either way; host-vs-device divergence = inherent GPU f32-atomic noise). The
gating hip train-parity tests were just fixed (commit `8aed100`). Now flip the default ON.

## Tasks

### Task 1 — Flip `RocmBackend::prefers_host_partition()` to default-ON
- **files:** `crates/lgbm-compute/src/lib.rs`
- **action:** The spike-035 gate currently reads `matches!(env "LGBM_ROCM_HOST_PARTITION", Ok("1"))`
  (default OFF). Flip to **default-ON with an OFF-switch**, mirroring the `LGBM_SIBLING_COPACK`
  idiom (`resident_pool.rs:282`):
  ```rust
  // spike-035 SHIPPED (quick-260626-a6t): route the rocm partition on the HOST via the shipped
  // spike-027 fused path instead of the per-split device round-trip — ~1.18-1.23x launch-bound,
  // wash at wide, parity within ~1e-6 (def-f8u-01; not a bit-exact swap). The device round-trip
  // is pure overhead on shared DDR5 (the build reads host indices_ either way). Default ON;
  // LGBM_ROCM_HOST_PARTITION=0 forces the old device round-trip for benching/rollback.
  fn prefers_host_partition(&self) -> bool {
      !matches!(std::env::var("LGBM_ROCM_HOST_PARTITION").as_deref(), Ok("0"))
  }
  ```
- **verify:** `cargo build --features rocm` compiles.
- **done:** rocm partition runs the host fused path by default; `=0` restores the device path.

### Task 2 — Full gate (CPU bit-exact merge gate + ROCm parity re-pin on the real GPU)
- **files:** none (tests only)
- **action:** run, all must be green:
  1. `cargo test -p lgbm-treelearner --lib` (default) — bit-exact, 77/0 expected.
  2. `cargo test -p oracle-harness` (default features) — the bit-exact CPU merge gate; MUST stay
     byte-green (CPU anchor path is untouched by this rocm-only change).
  3. `cargo test -p oracle-harness --features rocm` — full hip + kernel parity ON THE GPU. This
     is the re-pin: `hip::learner_parity_{resident,fused}_equals_host_tree_on_hip` (pin GPU tree
     to the cpu f64 anchor within ~1e-6) must PASS with the new default, plus
     `hip::kernel_parity_partition_exact_on_hip` and the rest of the hip suite.
- **PARITY DISCIPLINE (def-f8u-01, load-bearing):** this is NOT a bit-exact swap. The GPU f32
  atomic build is ~1.9e-6 nondeterministic regardless of partition path. Do NOT add or expect a
  host-rocm == device-rocm bit-exact assertion. The valid gate is the anchor-pinned hip tests
  above (GPU tree vs cpu f64 anchor within the ~1e-6 ROCm contract). If any anchor-pinned hip
  test regresses, STOP and report — do not loosen any tolerance.
- **verify:** all three suites green.
- **done:** gate green with host partition as the default.

# Quick Task 260608-kt8 — GPU-parallel f32-atomic histogram kernel

## Goal

Replace the single-unit (`CubeDim::new_1d(1)`) GPU histogram with a PARALLEL kernel
that uses all the GPU's lanes — one row per unit, f32 atomic-add into the global
histogram (gfx1100 `has_f32_atomic=true`). Parallel f32 accumulation reorders the
fold → the GPU path moves from bit-exact to the **~1e-6 ROCm gate** (CLAUDE.md's
intended GPU contract). CPU anchor untouched (still bit-exact, the merge gate).

## Tasks

- **T1 — parallel kernel + host wrapper (lgbm-compute, `#[cfg(rocm)]`).**
  `construct_hist_kernel_atomic_f32` (Array<Atomic<f32>>, one row/unit, bounds-
  checked) + `construct_histograms_parallel_f32_on<R>` (zeroed f32 out, launch
  CubeDim 256 × ceil(n/256), readback widened to f64).
- **T2 — wire RocmBackend.** `RocmBackend::construct_histograms` → the parallel
  kernel. GPU path is now ~1e-6 (f32), not bit-exact.
- **T3 — validate + benchmark (real gfx1100).** ~1e-6 parity test: parallel GPU vs
  CPU f64 anchor over a large random leaf. Kernel benchmark: parallel vs single-unit
  GPU on 20k rows → the speedup proof. End-to-end ~1e-6: train on GPU vs CPU within
  tol.
- **T4 — report/summary/state.** Honest kernel-level + end-to-end numbers.

## Gates

- Default (CPU) build UNCHANGED: oracle-harness bit-exact GREEN; atomics fully
  `#[cfg(rocm)]`-gated (no atomic codegen in the CPU build).
- `--features rocm`: parallel kernel within ~1e-6 of the CPU f64 anchor on the real
  GPU; faster than single-unit.

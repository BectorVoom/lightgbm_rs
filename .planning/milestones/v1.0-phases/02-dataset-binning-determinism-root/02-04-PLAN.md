<objective>
Deliver the minimal internal-facing ingestion API (D-05) — `from_mat` / `from_csr` / `from_csc` — and
`Metadata`, wiring the full pipeline: sample → `find_bin` (per column) → `Dataset::construct` → row-by-row
`PushData` → `finish_load`. Prove (a) dense vs CSR vs CSC of the same logical matrix bin identically,
(b) metadata round-trips with C++ query-weight derivation, and (c) an end-to-end `LightGBM/examples/`
dataset bins identically to the C++ golden (layers 1+2). All caller input is validated at the boundary
(Security V5) — typed `DatasetError`, never a panic.

Implements: D-05 (minimal `from_mat`/`from_csr`/`from_csc` only), D-06 (corpus #1 synthetic + #3 example
datasets), D-03 (sequential per-feature sampling/binning), D-04 (ingestion in the same crate).

Purpose: The only externally-callable surface this phase exposes, and the first end-to-end realistic
binning proof on real data — the dependency root Phase 3 (predict) and Phase 4 (histogram) read.
Output: `metadata.rs`, `ingest.rs`, dataset wiring, metadata/ingest-equivalence/example-parity goldens,
and the copied example-dataset fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `from_mat`/`from_csr`/`from_csc` | untrusted dense/CSR/CSC matrices + dims + metadata cross the ingestion boundary |
| caller → CSR/CSC `indptr`/`indices` | attacker-controlled offsets used to index `values`/columns |
| caller → label/weight/query vectors | lengths must match `num_rows`; query sum must equal `num_rows` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Tampering / Info Disclosure | `from_csr`/`from_csc` indexing on `indices[k]`/`indptr` | mitigate | Validate `indptr` monotone non-decreasing + last == nnz and every `indices[k] < num_cols`/`num_rows` BEFORE indexing; return `DatasetError::MalformedSparse`; no `unsafe` slice indexing on caller data. |
| T-02-11 | Denial of Service | shape/length mismatch (`data`, labels, weights, query) | mitigate | `from_mat` checks `data.len() == num_rows*num_cols`; Metadata checks label/weight lengths + query sum; all return typed `DatasetError`, never panic (Security V5). |
| T-02-12 | Denial of Service | `bin_construct_sample_cnt`/`num_rows` driving allocation + sampling | mitigate | `sample_count` clamps to `min(num_rows, bin_construct_sample_cnt)` (§12, Pitfall 6); reject negative `max_bin`/`min_data_in_bin`/dims via `DatasetError::InvalidConfig` before allocating. |
| T-02-13 | Denial of Service | degenerate input (0 rows, 0 features, all-NaN column) | mitigate | Mirror C++ guards (`is_trivial_`, empty-`used_features` warning); produce an empty-but-valid Dataset rather than panicking. |
| T-02-SC | Tampering | C++ example-capture harness compile | accept | Zero new packages (RESEARCH Package Legitimacy Audit). `LightGBM/`/`external_libs`/`examples` read-only, untracked, never `git add`ed (fixtures COPIED in); capture at regen time only. No `[ASSUMED]`/`[SUS]` package → no blocking-human checkpoint. |
</threat_model>

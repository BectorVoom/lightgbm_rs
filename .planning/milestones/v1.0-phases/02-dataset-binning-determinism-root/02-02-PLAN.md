factory (D-01), `DenseBin<T, const IS_4BIT: bool>` incl. the 4-bit packed variant (D-02),

not a stub.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BinMapper output → DenseBin/SparseBin push | bin indices feeding fixed-width storage slots + 4-bit packing |
| feature/bin counts → `num_total_bin_` accumulation | large feature×bin products risking offset overflow |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Denial of Service | `num_total_bin_` / `bin_offsets_` accumulation | mitigate | Accumulate in `u64` (mirror C++ `uint64_t`, dataset.cpp:383); use `as u64` widening for offset math so large feature×bin counts do not wrap. |
| T-02-05 | Tampering | DenseBin 4-bit `data_[idx>>1]` / SparseBin index | mitigate | Storage capacities sized from `num_data`/`num_bin` validated upstream; `data(idx)`/push use safe indexing (no `unsafe`); golden byte-layout tests prove no out-of-slot write. |
| T-02-06 | Tampering | SparseBin delta decode (`cur_delta` run-length) | mitigate | 255-run-length loop is bounded by `idx - last_idx` (non-negative post-sort); trailing-0 delta terminates; fast_index is a derived read-only acceleration table. |
| T-02-SC | Tampering | C++ storage-capture harness compile | accept | Zero new packages (RESEARCH Package Legitimacy Audit). `LightGBM/`/`external_libs` read-only, untracked, never `git add`ed; capture runs at regen time only. No `[ASSUMED]`/`[SUS]` package → no blocking-human checkpoint. |
</threat_model>

<objective>
Build the Phase-4 compute foundation AND settle the load-bearing D-04a determinism bet BEFORE any kernel suite is built. cubecl-cpu is NOT a single-threaded sequential executor — `runner.rs::execute_data` spawns one OS worker thread per cube unit and runs them concurrently (RESEARCH Pitfall 1). The entire D-04 "cubecl-cpu is the bit-exact deterministic anchor" architecture rests on the single-owner ordered f64 fold (`CubeDim::new_1d(1)`) being bit-stable. This plan proves that empirically with a minimal histogram kernel + an N>=20-launch spike, wires the `ComputeError` boundary type, the cpu/rocm runtime selection + startup capability gate (`Plane::Ops`/f64/atomic, asymmetric matrix per CMP-04), and the CMP-01 containment guard.

Purpose: De-risk the phase keystone. If the spike fails, the D-04a fallback (relax cubecl-cpu anchor to ~1e-6, reconsider a scalar reference) must be invoked here — at a decision checkpoint — before plans 04-02/03 build the full suite on the bit-exact assumption.
Output: `ComputeError`, runtime selection + capability gate, a minimal `construct_histograms` cube kernel, the determinism spike, the capability test, the CMP-01 containment guard, and the Cargo feature wiring (`cpu` default, `rocm` opt-in).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Phase-5 learner → `Backend` trait | Untrusted bin indices, grad/hess slices, and array lengths cross into kernel launches |
| host → cubecl kernel launch | `unsafe { ...::launch::<R>(...) }` with `ArrayArg::from_raw_parts` — handle/length correspondence is a safety invariant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering/DoS | `construct_histograms` input validation (Backend boundary) | mitigate | Validate `bin < num_bin`, `grad.len()==hess.len()==binned.len()`, `out.len()==2*num_bin` BEFORE launch → typed `ComputeError::BinIndexOutOfRange`/`LengthMismatch`, never a panic/UB (V5) |
| T-04-02 | Tampering | `unsafe` kernel launch (`from_raw_parts`, `launch`) | mitigate | Confine all `unsafe` to lgbm-compute; document the handle/length correspondence invariant at the launch call site |
| T-04-03 | Tampering | integer overflow in `bin << 1` index math | mitigate | Use `u32` widening exactly as C++ (`static_cast<uint32_t>(data(idx)) << 1`); validate `num_bin` fits and `2*num_bin` does not overflow the `out` allocation |
| T-04-04 | DoS | worker-thread stack overflow on deep kernels (cubecl-cpu) | accept | Kernels are iterative (not deeply recursive); 64MB default stack suffices; note `CUBECL_CPU_STACK_MB` for future deep kernels |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages introduced; cubecl 0.10.0 already vendored in Cargo.lock with checksums (RESEARCH Package Legitimacy Audit — all Approved) |
</threat_model>

<objective>
Close CR-01 (BLOCKER) and the root cause shared with CR-02 by adopting the
real-LightGBM `offset == 1` + compacted-histogram convention end-to-end for
`most_freq_bin == 0`, per user decision D-09. Today the port stores `offset == 0`
with a non-compacted histogram, so `split.rs:299` records `threshold = t + 0`
while `partition.rs:59-61` still applies the C++ `if most_freq_bin == 0 { th -= 1 }`
adjustment — the two boundaries disagree on the bin equal to `threshold`,
producing a partition (`[4,8]`) the serialized tree's own `get_leaf` does not
predict into (`[6,6]`). This is a silent ≥1e-12 fidelity violation of the
project's non-negotiable contract.

This plan: (1) introduces ONE shared `offset_for_most_freq_bin` helper and routes
every offset derivation (runtime learner + all harness corpora) through it,
deleting the three contradictory inlined rules; (2) makes the stored threshold,
the partition `--th` boundary, and predict routing self-consistent under
`offset == 1` compaction; (3) adds an oracle-INDEPENDENT regression assertion
that the grown tree's `get_leaf` row-routing reproduces the data-partition
`leaf_count` exactly.

Purpose: restore train/predict routing consistency — the phase's defining
contract — and unify the convention so the offset==1 path becomes actually
exercised (closing CR-02's coverage gap precondition).
Output: shared offset helper; corrected partition/threshold/compaction; a failing-
today routing self-consistency test that now passes.
</objective>

<objective>
Re-open the Phase-4 `Backend::find_best_split` boundary to thread the AUTHORITATIVE `skip_default_bin` / `na_as_missing` dispatch flags, replacing the Phase-4 `cfg_skip_default_bin(default_bin, num_bin)` heuristic (RESEARCH Pitfall 1). This is the enabling prerequisite for the Phase-5 spine's faithful missing/zero routing (TRL-05): the learner derives these flags per-feature from `bin_mapper.missing_type()` and `num_bin > 2` and passes them down, so the kernel dispatch matches C++ `feature_histogram.hpp:284-285` exactly.

Purpose: The current heuristic `default_bin < num_bin` is a documented Phase-4 approximation that diverges from the C++ predicate (`SKIP_DEFAULT_BIN = (num_bin > 2 && missing_type == Zero)`). For `missing_type == None` the heuristic can be true while the C++ flag is false — selecting a different threshold. Phase 5 inherits and resolves this.

Output: A widened `find_best_split` signature (trait + host fn) with explicit flags, the `cfg_skip_default_bin` heuristic removed from its two call sites, and an extended split golden + parity case proving the `skip_default_bin==false` (missing_type==None) path. The `na_as_missing` flag is plumbed through and validated false on every existing case; the NA_AS_MISSING forward-branch kernel body itself is explicitly out of scope here (see Artifacts) and deferred until a fixture forces it.

This is a Phase-4-boundary re-open: it changes the `find_best_split` trait signature in `lgbm-compute/src/lib.rs`. All existing callers (`kernel_parity.rs`) are updated in the same plan. The existing `kernel-capture` xtask subcommand is REUSED (no `xtask/src/main.rs` edit) — only the `kernel_capture.cpp` emitter content changes.
</objective>

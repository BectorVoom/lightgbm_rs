<objective>
Wave 1: the hot-path BUILD kernel (ODL-09). Lift the shipped Phase-11 u64 fixed-point LDS
accumulation body onto the §13 feature-partition geometry as a NET-NEW two-tier kernel
(D-03): `blockIdx.x` = feature partition, `threadIdx.x` = column, `threadIdx.y × blockIdx.y`
= row stripes; LDS block-local `Atomic<u64>` accumulation then a cross-block global atomic
merge (cubecl 0.10 has NO grid barrier, so cross-block reduction MUST be a global atomic).
Build both dense and sparse via one `#[cube]` generic with comptime branches, plus the
`_GlobalMemory` spill variant for large-bin partitions (D-04). De-quant the raw u64 to
hist_t ONCE after the merge (D-01, D-08 — no f64 per-row hot loop).

Purpose: this is the single most performance-critical kernel; it must be anchor-pinned to the
cpu f64 fold (D-06) and leave the shipped per-feature ROCm build byte-unchanged (D-03/D-07).

Output: the two-tier build kernel + de-quant pass + V5 launcher in `histogram.rs`, anchored to
the Wave 0 fixtures (dense corpora, sparse {16,32,64}, large-bin/global-spill, [2b]/[2b+1]).
</objective>

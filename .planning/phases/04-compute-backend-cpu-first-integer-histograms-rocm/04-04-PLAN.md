<objective>
Bring up the cubecl-hip (ROCm) backend on the local gfx1100 GPU and run the oracle suite against it — best-effort per D-03/D-03a. The capability gate (built in 04-01) is exercised against the REAL hip matrix (`Plane::Ops` YES, f64 NO, f32-atomic YES, plane_size 32, RESEARCH Pitfall 2): because hip has no f64, the histogram/subtract kernels accumulate in f32 on hip, which is the ~1e-6-tolerated divergence from the f64 cpu anchor (the exact divergence the contract was designed to absorb). The hip parity gate is SEPARATE from the cpu bit-exact gate: hip f32 output is compared to the cubecl-cpu f64 anchor (collected to `Vec<f32>`) within `ORACLE_TOL=1e-6` via `compare_within`. The CPU gate (04-01..03) remains the HARD phase-completion bar; any residual ROCm gap is a documented follow-up, not a blocker.

Purpose: Satisfy CMP-03 (hip selectable), CMP-04 (Plane API on hip with capability gating + sequential fallback), and the ROCm half of ORA-04 — while honoring D-03a (CPU-solid, ROCm-honest: surface gaps explicitly, never silent-pass).
Output: the `rocm`-feature runtime + f32-accumulate hip path, a feature-gated `rocm_smoke.rs`, the hip parity layer in `kernel_parity.rs`, and `04-ROCM-GAPS.md` documenting any residual gap.
</objective>

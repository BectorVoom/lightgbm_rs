Both fixes are mechanical and the C++ reference behavior is precisely specified.

Output: a corrected `from_params` pipeline in `set.rs` plus colliding-alias regression + determinism tests and empty-string-is-no-op regression tests.

For each incoming `(key, value)` classify via `resolve_alias`: if `resolve_alias(key) == key` the key is canonical-or-unknown; otherwise it is an alias mapping to `canonical = resolve_alias(key)`. Build the resolved map reproducing C++ `KeyAliasTransform` precedence exactly:

    (1) A directly-set CANONICAL key always wins over any alias targeting that same canonical (mirrors the second KeyAliasTransform loop: it only writes the alias value into `params[canonical]` when the canonical key is absent). So when both a canonical key and one-or-more of its aliases are present, the canonical's value is kept and the aliases are dropped.

    (2) For alias-vs-alias collisions onto the same canonical (no direct canonical present), pick the winner deterministically by `SortAlias` order on the ALIAS KEY NAMES: the alias whose key sorts FIRST under the tuple `(key.len(), key)` wins (shorter key first; on equal length, lexicographically smaller). This is the Rust port of `Config::SortAlias` — implement it as a helper that compares `(a.len(), a)` vs `(b.len(), b)`, or sort the colliding alias keys by that tuple and take the first. Do NOT use HashMap iteration order anywhere in the decision.

    The result must be a single deterministic value per canonical regardless of insertion/iteration order. Unknown (non-alias, non-canonical) keys still pass through with no error. Keep the rest of the pipeline (Stages 2-4) unchanged. Name `resolve_alias`, the `(key.len(), key)` SortAlias tuple, and the canonical-priority rule explicitly in the implementation.

    Add the three behaviors above to `crates/lgbm-core/tests/alias_resolution.rs` (or a new colliding-alias test module in that file): the canonical-beats-alias regression, the alias-vs-alias SortAlias-winner regression, and the N-run determinism test asserting a single distinct outcome.

<objective>
Deliver the hand-ported Rust `Config`: a single flat struct mirroring C++ `Config` 1:1 (same field names, same defaults), a static alias table ported verbatim from `config_auto.cpp::alias_table()`, a `from_params` pipeline that derives the six sub-seeds via the ported `Random` LCG, validates every in-scope C++ `CHECK_*` constraint as a typed `Result` error, and applies the in-scope `CheckParamConflict` mutations — all guarded by a drift-checker test that parses the C++ source and asserts coverage. Validation is exercised across a RANDOMIZED set of in-scope, boundary, and invalid parameter inputs (D-14), not a single fixed case.

Purpose: `Config` is the single config bag every later crate imports (mirrors the C++ single-`Config`-everywhere pattern). Its seed derivation, alias resolution, and validation are parity-load-bearing: a wrong sub-seed order or a missing CHECK silently corrupts downstream sampling and training. Per D-14, validation fidelity is proven across randomized in-scope/boundary/invalid combinations so the CHECK coverage is not a single-point claim. This slice closes the config half of the oracle contract and resolves RESEARCH Open Question 1 (the in-scope ~110 vs 131 auto-extracted split) with an explicit, drift-guarded scope set.

Output: `crates/lgbm-core/src/config/` (`mod.rs` struct+defaults, `alias.rs`, `set.rs`, `scope.rs`), unit tests for defaults/aliases/seed-derivation/validation (with randomized input coverage), and the `config_drift` test in the oracle harness.
</objective>

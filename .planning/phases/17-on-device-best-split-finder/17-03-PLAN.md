<objective>
Implement the Phase-17 numerical heart: the stage-1 per-(leaf,feature) split-evaluation core
(`split_eval_body`), driven single-owner on the cubecl-cpu f64 fold as THE bit-exact anchor
(D-01) and mirrored block-parallel on hip f32. This is where the CUDA §8.1 accumulation
diverges from the host `split.rs` serial scan, so all five parity landmines
(17-RESEARCH §"Common Pitfalls") concentrate here: round-ties-even count recovery, the
two-phase kEpsilon placement, complement-from-parent (no second scan),
`default_left = assume_out_default_left`, and the ReduceBestGain strict-> tie-break.

Purpose: SC#1 — one block per (leaf,feature) task runs block prefix-sum → cumulative
left/right sums → count recovery via cnt_factor + round-ties-even → min-data/min-sum-hessian
guards → gain math → forward/reverse default-bin scan → block argmax → per-task CUDASplitInfo.
Anchor-pinned to the cpu f64 fold; hip f32 within ~1e-6; never GPU-vs-GPU (def-f8u-01, D-08).

Output: `split_eval_body` + the cpu f64 fold launcher (makes best_split.txt goldens GREEN) +
the f32 hip launcher (net-new two-level LDS scan + ReduceBestGain) + V5 launch-boundary
validation. Additive, env-gated (D-09); NO f64 per-row hot loop (D-10) — f64 only in the
scalar gain/count math where §8.1 uses `double`.
</objective>

<objective>
Add the net-new `USE_SMOOTHING=true` (path_smooth) gain branch to `crate::gain` as ADDITIVE
`#[cube]` functions, and promote `get_leaf_gain_given_output` from a plain host `fn` to
`#[cube]` (+ f32 mirror) so the smoothing gain path runs on device. This is the only
genuinely net-new gain math in Phase 17: 17-RESEARCH §D-02 verified the CUDA device helpers
are bit-identical to the existing `crate::gain` functions for the three non-smoothing flags,
so those are reused as-is.

Purpose: The Wave-2 stage-1 numerical core (17-03) dispatches on the runtime `use_smoothing`
flag between the existing (reused) gain path and this new smoothing path. Building the
smoothing branch as a standalone gain unit — separate file from best_split.rs — lets it run
parallel to 17-01 in Wave 1 and be unit-tested against the hand-computed blend formula.

Output: additive `#[cube]` functions in `gain.rs`. CRITICAL: the existing `get_split_gains`,
`get_leaf_gain`, `calculate_splitted_leaf_output`, `threshold_l1` signatures are consumed by
`feature_histogram_categorical.rs` (host path) — they MUST stay byte-unchanged (D-09). The
smoothing path is NEW functions, never a signature change to the reused ones.
</objective>

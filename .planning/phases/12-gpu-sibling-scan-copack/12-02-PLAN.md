<objective>
Re-pin the resident-scan parity gate for the path Plan 01 added: a new `kernel_parity`
(`--features rocm`) cell asserts the co-packed 2-slot sibling scan
(`find_best_splits_fused_siblings_from_handles_on`) is (1) BYTE-IDENTICAL to two separate
single-slot scans of the same two histograms (the spike-024 correctness gate, productionized),
and (2) within ~1e-6 of the CPU f64 anchor (def-f8u-01: pin to the anchor, never GPU-vs-GPU).
Plus a cubecl-cpu W=1 cell proving byte-identity without rocm. Then confirm the CPU merge gate
stays green (no tolerance relaxed).

Purpose: SC-1 (bit-exact parity) + SC-2 (merge gate green). Co-packing is bit-exact by
construction -- each feature's sequential REVERSE+FORWARD scan is unchanged, only WHICH launch
it runs in changes (NO spike-016 reorder) -- so the co-pack SplitInfos MUST be byte-identical to
the two-separate-scan path (spike-024 proved B's two halves == A's two results, every cell). The
rocm-vs-anchor ~1e-6 pin guards the f32-vs-f64 envelope on the GPU; def-f8u-01 forbids comparing
two nondeterministic GPU paths to each other, so the anchor is the CPU f64 single-slot scan.

Output: the co-pack parity cell(s) passing on hardware + cubecl-cpu, and confirmation the CPU
merge gate (lgbm-treelearner, lgbm-boosting, oracle-harness goldens) stays green at existing
tolerances.
</objective>

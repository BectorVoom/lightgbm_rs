<objective>
Re-pin the resident-build parity gate FOR THE PATH PLAN 01 ACTUALLY CHANGED to a CPU f64
anchor now that the resident BUILD accumulates in u64 fixed-point, and add a determinism
assert proving the integer path is bit-equal across two runs. The new path is ~3600x more
accurate than the f32 path (5.9e-9 vs 2.2e-5 rel-to-anchor; exact in the cancelling regime),
so the re-pinned tolerance should TIGHTEN from the old f32-LDS gate toward exact where
justified.

> TARGET CORRECTION (vs the prior draft of this plan — recorded so the executor wires the
> RIGHT test): Plan 01 converts the resident BUILD that flows through `resident_raw_build_into`
> (consumed by `build_leaf_histograms_resident_f32_on` AND `build_fix_compact_resident_f64_on`
> / `RocmBackend::build_resident_leaf`). The ONLY committed test that exercises THAT path is
> `crates/oracle-harness/tests/kernel_parity.rs::kernel_parity_resident_build_fix_compact_equals_host_on_hip`
> (line ~1724). `crates/lgbm-compute/tests/rocm_cuda_mirror.rs::cuda_mirror_resident_matches_cpu_anchor_within_tol`
> drives a DIFFERENT kernel (`construct_hist_cuda_mirror_kernel`, the CUDA-faithful mirror)
> which Plan 01 LEAVES f32/UNCHANGED — so it is NOT the re-pin target. Worse: the oracle-harness
> resident test currently compares the GPU `build_fix_compact_resident_readback_f64_on` against a
> "host reference" (`build_leaf_histograms_resident_f32_on`) that is ITSELF a GPU launcher. After
> Plan 01 BOTH arms become u64-on-GPU -> a GPU-vs-GPU comparison with NO anchor (def-f8u-01
> violation). This plan re-pins that test to a fresh CPU f64 anchor.

Purpose: SPEC item 2 -- parity GREEN, pinned to the CPU f64 anchor within a TIGHTENED gate
(toward ~6e-9), CPU f64 bit-exact merge gate untouched, plus a 2-runs-bit-equal determinism
assert for the new integer path. def-f8u-01: NEVER pin two nondeterministic GPU paths to each
other -- always pin to the CPU f64 anchor.

Output: the re-pinned + determinism-asserting resident parity test that passes on hardware,
plus confirmation that the UNCHANGED non-resident f32 paths stay green at their existing
tolerances (no bit-exact pin relaxed).
</objective>

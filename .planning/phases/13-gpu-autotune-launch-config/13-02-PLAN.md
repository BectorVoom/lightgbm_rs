<objective>
Make CubeCL autotune the default selector for the histogram-build row-partition `P`, wired
at the single shared resident-build launch helper `resident_raw_build_into`
(histogram.rs:1758, the funnel for the live u64 fixed-point resident-pool chain AND the f32
readback/mirror paths). Replace the `row_partition_count(num_features, rows)` pick with a
tuner-driven launch over a `PSET` (e.g. {1,4,8,16,32}), keyed on the `log2(rows)` occupancy
regime, using a fresh-output InputGenerator (the build accumulates). Keep `row_partition_count`
as the documented `LGBM_AUTOTUNE=0` cold-start/fallback bound and add an `LGBM_AUTOTUNE_FORCE_P`
single-P seam for the 13-04 all-variants parity gate.

Purpose: Recover spike-040's ~10% (the heuristic under-partitions to P=1 at the 50-feature
production width) and self-calibrate on any future GPU, within the parity contract.
Output: `FreshOutGenerator` + `BUILD_TUNER` + the PSET builder + the wired launch, all in
histogram.rs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → launch | `LGBM_AUTOTUNE_FORCE_P` is untrusted process input controlling a launch dimension. |
| persisted cache → launch | `target/autotune/0.10.0/<device>/*.json.log` is read to pick the variant across processes. |
| benchmark reps → device buffer | The cold tune launches the accumulating build kernel N× — the corruption hazard. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-02-01 | Tampering | `LGBM_AUTOTUNE_FORCE_P` value | mitigate | Parse + `clamp(1, ROWPART_P_MAX)`; non-numeric → `None` (falls through to autotune/heuristic); never a no-launch. |
| T-13-02-02 | Tampering | Accumulating build corrupted by benchmark reps | mitigate | FreshOutGenerator isolates the benchmark `out`; a debug grad-conservation assert guards it (spike-038). |
| T-13-02-03 | Tampering | Poisoned autotune cache file picks a different (still-correct) P | accept | Every PSET variant is parity-gated to the CPU f64 anchor (13-04); a wrong pick is at worst a perf regression, never a numeric fault. |
</threat_model>

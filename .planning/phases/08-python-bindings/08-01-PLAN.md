<objective>
Close the Rust-side enabling slice for Phase 8: the D-02 raw→bin→train wiring gap in
the `lgbm` facade, plus the missing `Booster` delegation methods (batch predict,
feature importance, refit, model text I/O) AND the custom-metric (feval) eval-history
hook on the custom-train path. This is the slice everything Python depends on — the
Python layer cannot call what the facade does not expose, and the Python feval
marshalling in 08-06 cannot wire a user metric into eval history unless the facade
exposes a custom-metric closure here first.

Purpose: Per D-02, the raw→bin→train wiring lives in the Rust facade (not Python),
so Rust users benefit and it is oracle-testable in Rust. This is integration of the
already-bit-exact `BinMapper`/`Dataset::construct` binning — NOT new binning, NOT
scope creep (D-01/D-02). The facade custom-metric hook is the mandatory upstream
half of PYB-04's custom-metric requirement: today `train_custom` (booster.rs:349-367)
accepts ONLY a custom objective and hard-codes `metrics = vec![EvalMetric::Reg(Metric::L2)]`,
and the eval-history loop (booster.rs:593-698) builds history exclusively from that
built-in list — there is NO user-metric injection point, so 08-06 must consume a hook
that does not yet exist.
Output: A `RawCorpus`-driven train path through `BinMapper`, new public `Booster`
methods delegating to `GbdtModel`/`model_text`, a custom-metric (feval) closure
parameter on the custom-train path feeding the eval-history loop, and a Rust oracle
test proving raw binning reproduces the identity-bin / C++ golden output.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → facade `train_raw`/`Booster::*` | Rust caller (ultimately the PyO3 layer) passes raw feature rows, labels, model text — untrusted lengths/shapes cross here |
| custom feval closure → eval-history loop | the custom-metric closure returns a `(name, value, is_higher_better)` triple each eval — value range/NaN untrusted |
| model text → `model_from_string` | untrusted serialized model text parsed into a GbdtModel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Tampering/DoS | `build_feature_columns_from_raw` shape handling | mitigate | Validate non-empty corpus, `labels.len()==num_data`, rectangular rows → `LgbmError::InvalidCorpus` BEFORE any indexing/binning (Security V5) |
| T-08-01-02 | DoS | facade methods on malformed input | mitigate | No `unwrap`/`expect`/`panic!` on user input; every fallible method returns `Result<_, LgbmError>` |

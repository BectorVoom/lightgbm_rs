<objective>
Close BLOCKER **CR-03**: make the Rust `SerialTreeLearner` reproduce the REAL
`lib_lightgbm` 4.6 goldens (`spine_real.txt` / `mfb_pos_real.txt`, captured in
05-06 under D-08) BIT-EXACT, then un-`#[ignore]` the two real-binary parity gates
that currently FALSIFY the port.

05-06's real oracle exposed that the learner grows STRUCTURALLY WRONG trees:
on the spine corpus wrong split points / mis-partitioned `leaf_count` / leaf
outputs like `-17.99` where the golden has `0.55`; on the most_freq_bin>0 corpus
a leaf with ZERO rows (`leaf_count=[4,6,0,2]`), `decision_type[0]=0` instead of
`2`, and a MISSED zero-sentinel threshold (`1.0000000180025095e-35`) on the
offset==1 default-bin split.

The likely single root cause (to be CONFIRMED by Task 1's diagnosis, not assumed):
`find_best_split_cpu` (`split.rs`) runs BOTH the REVERSE and FORWARD scan branches
in one kernel for every call, but for `missing_type == None` (the only case both
corpora use) real LightGBM dispatches ONLY the REVERSE branch
(`feature_histogram.hpp:420-429`: the sole call is
`FindBestThresholdSequentially<TEMPLATE_PREFIX, true /*REVERSE*/, false, false>`;
FORWARD is never invoked). `FindBestThreshold` pre-sets `output->default_left =
true` (`:170`) and the REVERSE finalization sets `output->default_left = REVERSE
= true` (`:1055`), so for `missing_type==None` default_left is ALWAYS true →
`decision_type == 2`. By also running FORWARD, the Rust kernel lets the forward
branch win some nodes (setting `default_left=0` → `decision_type=0`) AND select a
different threshold/partition, cascading into wrong `leaf_count` and wrong Newton
leaf outputs. Restricting the branch set to LightGBM's per-`missing_type` dispatch
restores the REVERSE-only winner (correct split, `decision_type=2`, and the
bin-0/zero-sentinel split on mfb>0).

Purpose: restore bit-exact learner fidelity vs the real binary — the
non-negotiable contract (CLAUDE.md) — and unblock 05-07.
Output: a `missing_type`-faithful branch dispatch in `find_best_split` +
the two real-binary gates un-ignored and passing.
</objective>

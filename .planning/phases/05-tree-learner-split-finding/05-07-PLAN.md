<objective>
Close WR-01 + WR-02 (Warnings degrading the TRL-02 claim) by wiring the
subtraction trick and HistogramPool into the ACTUAL growth path. Today the
orchestration is dead: `find_best_splits` always calls `construct_histograms`
directly and discards the sibling id (`let _ = subtract_from;`, learner.rs:741),
and the pool is passed as `_pool` and never read (learner.rs:546). The trick is
bit-exact in isolation (`learner_parity_subtract`) but the claimed orchestration
— "the larger child's histogram is derived by subtraction" (TRL-02, D-05 locked
"mirror the full C++ histogram pool + eviction faithfully") — does not run.

With the offset convention unified (05-05) and a REAL lib_lightgbm oracle in
place (05-06), wiring the trick is now meaningfully validatable: the derived-vs-
direct equivalence holds for f64 histograms, and the grown tree must still match
the real goldens bit-exact. This plan makes `find_best_splits` build only the
SMALLER child directly and derive the LARGER child by `parent − smaller` via
`Backend::subtract_histograms`, reading/reusing pool slots for the parent and
children exactly as C++ `serial_tree_learner.cpp` does.

Purpose: make the keystone subtraction-trick + pool orchestration actually
execute (not just pass in isolation), restoring full TRL-01/TRL-02 fidelity.
Output: live subtraction/pool growth path + a parity test that the wired path
still matches the real goldens.
</objective>

<objective>
Close CR-02 (BLOCKER) per user decision D-08: replace the hand-transcription
learner oracle with a REAL `lib_lightgbm` 4.6 oracle. The committed goldens today
are emitted by `learner_capture.cpp`, which shares the port's offset/`--th`
conventions and so validated the port against itself — it could not falsify the
shared-convention errors. The Phase-3 `model-capture` already proves the
mechanism: the pip-installed `lightgbm` 4.6 ships a real prebuilt `lib_lightgbm`
(with `fmt` baked in) whose `save_model()` IS authoritative. (Vendoring
`external_libs` to build `lib_lightgbm` from source is infeasible here — the
submodules are empty — so the pip wheel is the real binary, exactly as Phase-3
human-approved.)

This plan adds a one-time `learner-oracle-capture` xtask subcommand + python
script that trains the spine corpus AND a NEW `most_freq_bin > 0` corpus on real
`lib_lightgbm` 4.6 with `deterministic=true force_row_wise=true num_threads=1`
fixed seed, dumps the real model text, and commits it as `spine_real.txt` /
`mfb_pos_real.txt`. learner_parity.rs then compares the Rust learner's grown tree
against these REAL reference trees via the existing Phase-3 `%.17g` model-text
machinery — bit-exact on CPU. Routine `cargo test` replays the committed goldens
with no toolchain.

Purpose: anchor both the spine AND the offset==1 path against a real binary so
CR-01/CR-02 shared-convention errors are falsifiable; give the offset==1
scan+partition path (fixed in 05-05) its first real bit-exact coverage.
Output: real-binary goldens + capture subcommand + offset==1 parity test.
</objective>

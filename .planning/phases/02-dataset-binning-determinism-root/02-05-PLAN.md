<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| feature sample indices → EFB conflict counting | per-feature non-zero marks drive grouping; large feature counts |
| group/offset accumulation → num_total_bin_ | bundled groups accumulate offsets risking overflow |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Denial of Service | `find_groups` greedy loop / `num_total_bin_` accumulation | mitigate | Group search is bounded (sample up to 99 + last group per feature); accumulate `num_total_bin_` in `u64` (mirror C++ `uint64_t`); conflict counting early-returns -1 past `max`. |
| T-02-15 | Tampering | `get_conflict_count`/`fix_sample_indices` index into sample marks | mitigate | Indices derived from validated ingestion (Plan 04); bounds-checked iteration, no `unsafe`; `fix_sample_indices` only runs when `default_bin != most_freq_bin`. |
| T-02-16 | Tampering | non-determinism from RNG/sort drift | mitigate | ALL randomness via `lgbm_core::Random::new(num_data)`; STABLE sorts only; element-wise parallel-vector swap — golden layer-3 test catches any drift. |
| T-02-SC | Tampering | C++ EFB-capture harness (focused or full-CLI build) | accept | Zero new packages (RESEARCH Package Legitimacy Audit). `LightGBM/`/`external_libs` read-only, untracked, never `git add`ed; capture at regen time only (Task 3 resolves focused-vs-CLI). No `[ASSUMED]`/`[SUS]` package → the human checkpoint here is feasibility-resolution, not package legitimacy. |
</threat_model>

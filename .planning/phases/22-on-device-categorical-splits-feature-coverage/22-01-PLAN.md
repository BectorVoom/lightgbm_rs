<objective>
Land the two config-boundary guardrails that the categorical device path depends on, both
additive and both leaving the default (`LGBM_CUDA_ON_DEVICE` unset) lane byte-unchanged:

1. **D-03 runtime slab width.** `MAX_CAT_PER_SPLIT` (split_info.rs:65) is currently a fixed
   `const usize = 32`. Make the categorical slab *width* a runtime value read once from
   `config.max_cat_threshold` at `DeviceSplitInfo::new` (default 32). `MAX_CAT_PER_SPLIT`
   becomes the DEFAULT, not a hard cap — any `max_cat_threshold > 32` config is faithful with
   NO silent truncation and NO per-split alloc (allocate-once, ODL-02 preserved). Explicitly
   rejected by D-03: hard-clamp-to-32.
2. **D-06 host-fallback gate.** The CUDA reference `asm("trap;")`s on categorical+quantized —
   it has no on-device categorical+quantized path. `on_device_eligible` (learner.rs:498) must
   AND-in `!(has_categorical_feature && config.use_quantized_grad)` so that combo routes to the
   host with a one-line log. This check MUST live in the learner (where `use_quantized_grad` and
   `bin_type` are visible); `on_device_growth_supported()` takes no config args (RESEARCH A4).

Purpose: SC #1 needs faithful slab sizing before the §6.3 bitset writes into the slabs; SC #4
needs the categorical+quantized combo to fall back honestly (no silent wrong answers). Both are
prerequisites the transcription/wiring plans build on.
Output: a runtime-width `DeviceSplitInfo` + a config-aware eligibility gate, each with a unit
test; the numerical spine and merge gate untouched.
</objective>

Close the D-01 dual anchor for the categorical device path — the fidelity UPGRADE that makes
categorical the FIRST on-device subsystem pinned to a REAL reference (not a re-transcription).
This plan extends the existing harness (it MERGES two twins rather than building new ones):
`learner_parity_on_device_structure_gate` (:2329, the D-01#2 device structure gate, currently
numeric-only) and `run_categorical_cell`/`cat_corpus` (:1486/:1454, the D-01#1 real-4.6-golden
HOST cell).

Two anchors, both against the DEVICE-grown tree:
1. **D-01 #1 — real 4.6 goldens bit-exact.** For `cat_onehot` and `cat_manyvsmany`, grow the
   tree through the DEVICE driver and assert bit-exact vs the committed goldens: `num_cat`
   (:1500-1518 asserts to reuse), the `kCategoricalMask` decision-type bit (`dt & 1`),
   `cat_boundaries`, and the REAL category bitset `cat_threshold`. Proves REFERENCE fidelity of
   the split math on-device.
2. **D-01 #2 — cubecl-cpu f64 structure gate.** Add categorical corpus cases to
   `learner_parity_on_device_structure_gate` that drive the device driver and compare against
   the cpu f64 anchor with the tie-aware `default_left` comparator (CpuBackend runs f64-vs-f64 →
   structure bit-exact). Proves the full device grow loop routes categorical rows correctly.

Plus predict-through: round-trip prediction through the categorical bitset on the DEVICE tree
(reuse the `run_categorical_cell` predict path, :1522, now against the device tree).

The gate runs on the DEFAULT cubecl-cpu f64 lane so it is non-vacuous without ROCm hardware
(D-04: ROCm is best-effort smoke, not the gate). Anchored to the cpu f64 fold, never GPU-vs-GPU
(def-f8u-01). Purpose: SC #1/#2/#3 verified through the device path; SC #4 preserved.
Output: the two real-golden categorical cases + the device structure-gate cases, all green.

<objective>
Wire the categorical path end-to-end through the on-device grow driver — the ~70%-wiring core
of this phase. The §9 partition membership and §10 `SplitCategorical` mutation and the predict
branch ALREADY EXIST, compile, and are anchor-tested (RESEARCH Summary); this plan connects them
to the §8.1 evaluator (22-03) and the driver, replacing the two bail-out seams:

1. **`best_split.rs` dispatch seam** (:640-643, :958-960, :1814-1816) currently returns the
   `is_valid=false` sentinel on `task.is_categorical`. Replace with a call into the 22-03
   evaluator, mapping `CategoricalSplit` → `SplitScalars` (mirror the numeric mapping already in
   the function). The task flags `is_categorical`/`is_one_hot` are already set (:98-102, :239-243).
2. **`grow_driver.rs` scan_leaf** (:384) currently `continue`s on `BinType::Categorical`. Split
   the condition: keep `na_as_missing` deferred, but ROUTE `BinType::Categorical` into the
   evaluator. **Pitfall 2:** the driver must bump `sum_h` by `+2*kEpsilon` BEFORE calling the
   categorical evaluator (numeric bumps internally; categorical expects pre-bumped, host does it
   at learner.rs:2760). In the driver body, for a categorical best split: stage the chosen
   thresholds into the pre-allocated `DeviceSplitInfo` cat slab, construct the real + inner
   bitsets (22-03 `set_real_threshold`), set `num_cat_threshold` on the `SplitScalars`
   (numeric uses 0, :637), then call the EXISTING `tree.split_categorical_on_device(...)`
   (tree.rs:765, §10) and `partition_categorical_on_device(...)` (data_partition.rs:686, §9)
   instead of the numeric `split_on_device` / `partition_leaf_stable`.
3. **Open Q1 isolation** — before the full structure gate (22-05), a lgbm-compute unit test
   asserts the on-device categorical partition counts equal the host `partition_categorical_stable`
   (data_partition.rs:525) for both fixtures, isolating the real-value-vs-inner-bin routing
   convention (Pattern 3 / Pitfall 4) as a standalone signal.

**SC #1 — pre-allocated representation is END-TO-END (W-3).** The chosen categorical thresholds
land in the pre-allocated `DeviceSplitInfo` cat_threshold slab (the D-03 runtime-width slab from
22-01) via `set_cat_thresholds` on the LIVE categorical grow path — allocate-once, NO
per-`SplitInfo` device alloc (ODL-02). The host `Vec<u32>` real/inner bitsets that
`split_categorical_on_device` consumes as slice args are the transient materialization DERIVED
from those slab-staged thresholds (via `set_real_threshold`), not a parallel per-split
allocation. This ties 22-01's slab to the live path (not only the width>32 unit test), so SC #1's
"pre-allocated representation" is demonstrably wired end-to-end, not nominal.

**kEpsilon single-bump contract (W-4).** There is EXACTLY ONE `+2*kEpsilon` bump of `sum_h` on
the categorical path, and it lives in the DRIVER (Task 2), mirroring host `learner.rs:2760`. The
`best_split.rs` seam (Task 1) PASSES THROUGH the already-bumped value — it does NOT bump. The
22-03 evaluator does NOT bump internally (its caller contract). Double-bump or missed-bump is a
last-ULP silent divergence (DEF-07-11-01 class) that the structure gate could pass while leaf
values drift, so it is pinned by a targeted assertion (Task 2), not only by the end-to-end gate.

Everything additive, behind `LGBM_CUDA_ON_DEVICE`; numeric spine byte-unchanged (SC #4).
Purpose: SC #1 (bitset via the pre-allocated slab, end-to-end) + SC #2 (categorical eval +
partition membership routed by `CUDAFindInBitset`) + SC #3 (SplitCategorical mutation via the
existing §10 entrypoint). Output: a driver that grows a categorical tree on-device by calling the
existing kernels.
